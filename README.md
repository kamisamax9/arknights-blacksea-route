> 《明日方舟》集成战略「黑流树海」的**逐步路线决策**技能。
> 不排一条走两步就作废的死路线：每走一步、每探明一格、每换一次道具，都按最新状态重算下一步。

## 它解决什么问题

黑流树海的路线规划不是「从 A 到 B 找最短路」：

- **连通关系固定、但每局地图随机**——同一层通常有 3~10 种构型（六层按结局各 1 张图），边只能查构型表，不能看截图猜；
- **信息逐步揭示**——未知节点只能按距离带和数量配额算期望，探明一格就要重估；
- **资源是预算不是距离**——AP 必须花完，跳跃件是「1 AP 覆盖 d 格」，用错就少打一整格；
- **规则带分支**——分队模式改写定价，终点模式改写终点，二/三/四结局再各自加一层约束。

所以本技能的输出不是一条静态路线，而是：

| 玩家给 | 技能给 |
|---|---|
| 层数、起点、AP、现金、库存（截图或口述） | 这一步走哪、用什么道具、预期收益 |
| 理想源（树根）坐标、各层问询答案 | 备选是什么、为什么不如它 |
| 「探明了什么 / 掉了什么 / AP 剩多少」 | 什么条件下要重算 |

### 三个设计选择

1. **表 > 图**：连通只认 `references/` 的构型边表；截图有遮挡/暗线/缩放失真，不能用来加边或删边。
2. **判词 > 作文**：模型只转述求解器结论（`✅/❌` + `--explain` 文案），不自行补充规则。
3. **人报 > 识别**：当前位置、树根坐标、库存以玩家口述为准，截图只是佐证。

## 快速上手

本技能放在工作区 `.dsh/skills/` 下由 DSH 自动发现；工具链也可脱离 DSH 直接跑。
以下命令从**工作区根目录**进入技能目录后执行：

```bash
cd .dsh/skills/arknights-blacksea-route
```

### 0. 先自检环境

```bash
python tools/pyenv.py
```

它会打印**当前解释器**、缺哪些依赖；缺依赖时列出本机依赖齐全的解释器。

```text
当前解释器：...\Python311\python.exe
必需：numpy✅  PIL✅  rapidocr_onnxruntime✅  onnxruntime✅
✅ 当前解释器依赖齐全 —— 直接用它跑 `python tools/xxx.py` 即可。
```

> ⛔ `pip` 所属的 Python 不一定是跑脚本的 Python——报「缺依赖」之前先看这里打印的解释器路径。

想先确认链路而不开游戏：用自带示例跑一次
`python tools/route.py tools/examples/scene-L3-real.png --layer 3 --config L4 --ap 6 --root 4,3 --items "标准引擎:2;鸣笛:1"`，
应输出 `✅ 可用`（示例图是三层 L4，树根 (4,3)）。

### 1. 开局先问两个开关

新对话第一次规划时，必须先问清（相互独立，都要问）：

- **分队模式**：`N16文明开化` 还是 `普通分队`？
- **终点模式**：`全程追猎` 还是 `险路尽头`？

两轴正交，任意组合合法；N16文明开化推荐搭配全程追猎（理想源是「追猎进入时大概率出现」）。
工具**有默认值**（N16 / 全程追猎），但不传不会报错、只会静默按默认口径算——所以不能靠默认。

### 2. 进新层：一条命令

```bash
python tools/observe.py --mode N16文明开化 --end-mode 全程追猎 \
    --items "标准引擎:3;试作外骨骼:2" --explain
```

`observe.py` 会一次做完：**截图 → 标题 OCR 认层 → 小人定起点 → 起点+地标定构型 →
读 AP/节点/徽章 → 建场景 → 求解 → 全量校验 → 判词**。

玩家只需补图上没有的：

- **理想源坐标**（N16 二~六层必报；普通分队不报 = 本层无理想源）。
- **道具库存**：`--items` 默认口径是「件数」（`标准引擎:2` = 2 件 = 6 次；只剩 N 次写 `剩N次`）；
  道具名必须用**全名**，写简称会抛 `UnknownItem`，全名见 `references/01-加工品.md`。
- **各层必答问询**（见下一节）。

装了 `dsh-plugin-arknights-grab` 时，模型可直接调 `arknights_grab` 拿截图与节点表；
没有插件就用 `python tools/grab.py --scene`，再不行请玩家手动截图。

### 3. 层内每一步：滚动重算

```bash
python tools/route.py 截图.png --layer 3 --config L4 \
    --mode N16文明开化 --end-mode 全程追猎 \
    --start 6,3 --ap 8 --visited "0,2;6,3" --root 6,3 \
    --items "报废轮子:2;结构性原理:1" --explain
```

两个模式开关在**每条命令**上都要透传（`--mode` / `--end-mode`），不要只传一次。

- `--start` 是**玩家当前所在格**，不是进层起点；
- `--visited` **必带**（已走过的格），否则打过的树根会被当成没打过，重复计分、重复发 +2 AP；
- `--root` 仍要传：树根坐标只能人报，`--visited` 只抽掉它的 +2，不改节点类型。

进层那一刻用 `observe.py`，之后每一步用 `route.py --start/--visited`，两个命令别混用。

### 4. 怎么读结果

最后一行永远是判词：

```text
✅ 可用
✅ 可用（回头步均为必经）
❌ 不可用：<原因>
```

加 `--explain` 会另附一段转述文案：【结论】【下一步】【备选】【再看】【风险】。

> ⛔ **输出门禁**：回复里出现上述任一栏目，本轮必须同时给出 `observe.py`/`route.py` 的判词；
> 给不出判词就只能报告识别结果或向玩家提问，不许自由作文。

## 两个开关与三道必答闸

| 时机 | 必须问清 | 参数 | 不答的后果 |
|---|---|---|---|
| 新对话首次规划 | 分队模式 | `--mode <N16文明开化｜普通分队>` | 静默按 N16 算（禁止） |
| 同上 | 终点模式 | `--end-mode <全程追猎｜险路尽头>` | 静默按全程追猎算（禁止） |
| 二层 | 四结局；险路尽头模式下答「要」再问是否已获取前置藏品 | `--four-ending <要｜不要>` `[--four-ending-pre <已获取｜未获取>]` | exit 2，拒绝求解 |
| 三层且本层无右区 | 三结局；答「要」再问前置收藏品 | `--three-ending <要｜不要>` `[--three-ending-pre <已获取｜未获取>]` | exit 2 |
| 五层且左区 3 个命运所指 | 二结局；答「要」可手报带徽章坐标 | `--second-ending <要｜不要>` `[--second-ending-node c,r]` | exit 2 |

- 问询只看层数与图上事实，不看玩家是否主动提；同一局滚动重算沿用答案，不必重复问。
- **三层有右区时不要问三结局**（有右区 = 走四结局线），也别传参数，否则工具按「用错」报错。
- **右区（熄日余径）有无自动判**：三/四/五层按格点宽度（完整 11/12/14 vs 左区 7/8/10；L8 为 9）。
  只有已获取四结局前置藏品才有右区；三结局前置已获取同样无右区。拿不准就问玩家后传 `--right-zone 有/无`。

## 工作原理

```text
进层：截图 → 认层 → 小人定起点 → 起点+地标定构型 → 读 AP/节点/徽章
      → build_scenario 建 scenario → route_solver 求解
      → route.py 复核（起点/构型/AP 收支/回头步/必走点/终点类型）→ ✅ / ❌

滚动：玩家报当前位置/新探明 → route.py --start/--visited
      → 重算下一步 → ✅ / ❌ + 转述文案
```

- 三/四/五层有右区时默认**分阶段**求解（左区、右区各自最优再拼接），`--joint` 切整体；
  险路尽头模式下这三层自动整体求解（「最后一步落在尽头/恶敌」是全路线性质）。
- 分阶段显著更快，代价是可能丢 0~11 分的跨区组合；要最优就 `--joint`。
- 求解目标分两段：先最大化总分，同分再最小化道具消耗。

## 一页速查（硬常数）

| 层 | 网格 | 基础 AP（追猎／险路尽头） | 右区（熄日余径） |
|---|---|---|---|
| 一 | 5×3 | 6 ／ 6 | 无 |
| 二 | 5×4 | **5 ／ 6** | 无 |
| 三 | 11×5 | **6 ／ 7** | 3 列 |
| 四 | 12×5 | **7 ／ 8** | 3 列 |
| 五 | 14×5（L8 变体 13×5） | **7 ／ 8** | 3 列 |
| 六 | 5×4（四结局）/ 6×5（三结局源流） | **4 ／ 5**（有树根/理想源则 +2 = 6 ／ 7；普通分队 4 ／ 5） | 无 |

- **追猎进入二~六层会消耗 1 行动力**，所以全程追猎每层比险路尽头少 1 点；一层不受影响，且只与终点模式有关、与分队模式无关。
- 坐标 `(0,0)` 在**左下角**，x 向右、y 向上；`(列, 行)`。
- **AP 是必须花完的预算**，不存在「省下来」；1 次移动 = 1 个节点，跳跃 = 1 AP 覆盖 d 格。
- 一层默认无理想源；六层四结局固定解（追猎 4 + 树根 2 = 6 步；险路尽头 5 + 2 = 7，但末步若为险路恶敌，多出的 1 点可能用于补终点），
  且**所有加工品在该层每件只剩 1 次**；三结局「源流」不夹次数、基础 AP 4 ／ 5。
- 构型命名：一/二层 `1`~`3`/`1`~`10`；三/四/五层 `L1`~`L10`；六层 `唯一`（四结局）或 `源流`（三结局）。

> 详细定价与例外一律查 `references/03-节点收益.md`、`references/04-推演规则.md` 与 `tools/rules.py`。

## 状态文件与文件纪律

每局维护一个 scenario JSON，**它是唯一事实**；每次只增量更新，不重建：

| 字段 | 含义 | 何时改 |
|---|---|---|
| `start` / `edges` | 进层起点 / 构型边表 | 进层定一次，之后不变 |
| `nodes` | 每格当前已知类型 | 每次探明（`凶戾`→`紧急作战`、`诡秘`→`得偿所愿`） |
| `values` | 本层定价 | 由 `rules.py`/建场景生成，一般不手改 |
| `ap` / `grants` | 当前行动力 / 尚未领取的 +AP | 每步 |
| `items` | 库存（件数与剩余次数） | 用掉/买到 |
| `got` | 已访问格 | 每步追加 |
| `mode` / `end_mode` | 两个模式开关 | 全局不变 |
| `four_ending` / `three_ending` / `second_ending` | 必答问询答案 | 全局不变 |
| `has_right` / `final_type` / `final` | 右区有无 / 终点约束 | 进层或问询后定 |
| `clamp_items_at` | 进入后所有加工品次数强制→1（五层二结局的右区命运所指） | 问询后定 |

文件纪律：

- **runs 只有一个**：工作区根的 `runs/`；场景命名 `L{层}-c{构型}-{HHMM}.json`，例如 `runs/L1-c3-1535.json`。
- **每层只留一份**：重算直接改它或同名覆盖；时间戳只用于区分不同对局，不是每次新建。
- **坐标不落盘**：坐标每次现算，存下来就过期；不要建 `tmp_*.json`、`_A.json` 这类临时文件。
- 每层结束前：`python tools/sweep_runs.py --dry-run` 预览，再 `python tools/sweep_runs.py` 真删。
- 不要手抄 OCR 表格进 scenario——2026-10-27 一天内因此出过三次事故。

### 必跑回归

| 改了什么 | 必跑 |
|---|---|
| 求解器 / 定价 | `python tools/selftest_solver.py`，再 `python tools/regress.py --quick` |

## 常见问题

**Q：抓图失败怎么办？**
先 `python tools/observe.py --probe` 看链路；再 `--adb <路径>` / `--device 127.0.0.1:16384`。
仍失败就让玩家现场截图后 `--image`（必须 5 分钟内；只有复盘才 `--allow-stale`）。
⛔ 不要翻 `runs/shots/` 里的旧图——那是别的对局/别的层。

**Q：认不出层？**
标题 OCR 是唯一权威；认不出时用 `--layer N` 兜底（`observe.py`/`route.py`）；
`grab.py`/`label_ocr.py` 还可用 `--cols/--rows` 指定网格。
⛔ 不要默认 11×5 硬读（2026-10-29 一层就是这么读错的）。

**Q：工具报「起点不符」/ 和玩家说的位置冲突？**
以玩家口报为准：滚动时用 `route.py --start c,r` 覆盖，进层识别时用 `label_ocr.py --start c,r`；
截图只作佐证。构型冲突先停下核对，别硬算。

**Q：右区到底有没有？**
工具按格点宽度自动判；拿不准就问玩家后传 `--right-zone 有/无`。
无右区时不预留 AP、右区必走点全部失效，也不许再报「右区没进去」。

**Q：二层/三层/五层直接 exit 2？**
必答问询没完成（见「两个开关与三道必答闸」）。补齐参数再跑，同一局滚动沿用答案。

**Q：缺 OCR / 缺 scipy？**
先跑 `pyenv.py` 看解释器路径。缺 OCR → 让玩家口报，**不要**退回色度猜类型；
缺 scipy → 滚动起点判定会打 ⚠️ 降级，不是静默失败。

**Q：`runs/` 目录很乱？**
`python tools/sweep_runs.py --dry-run` 预览会删什么，确认后再真删。规范是每层一份。

**Q：六层为什么步数这么少？**
六层基础 AP 追猎 4 / 险路尽头 5；N16 打树根/理想源 +2 → 6 ／ 7 步，普通分队 4 ／ 5 步。
四结局「盲目者所见」所有加工品在该层每件只剩 1 次；三结局「源流交汇处」不夹次数、按默认耐久。

**Q：结果违反直觉，能直接改吗？**
先怀疑模型缺规则（查 `references/19-已知坑.md`）。人可以否决程序的最值，但**必须给理由**，
写进 `tools/offline/exceptions.json` 或 CHANGELOG——每次否决 = 一条新规则。

| 能做 | 不做 |
|---|---|
| 按构型边表求最优/次优路线 | 不替你操作游戏（截图只读，不点按钮） |
