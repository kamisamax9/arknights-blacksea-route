# 右区（熄日余径）可能存在，也可能不存在（2026-10-30 玩家口径）

## 规则

**三/四/五层的右区（熄日余径）只在「已获取四结局前置藏品」时出现。**
前置藏品来自一层或二层；没拿到时：

- 这三层**只有左区**，左区在屏幕/截图里**直接居中**；
- **不预留行动力给右区**（三层 3 / 四层 4 / 五层 5 点全部归左区）；
- 右区的**所有必走点、收益、作战配额、行商/诡秘推断全部失效**；
- 不许再报「右区没进去 / 右区无解 / 右区格数不对」——这些检查只属于有右区局。

有右区时，才按原来的「左区 + 1 列缝 + 3 列右区、右区纵向浮动 3 档」求解，
并保留右区固定节点数校验（三层 6 / 四层 7 / 五层 9）。

## 三层「无右区」还要多问一道题（2026-10-30）

**三层没有右区 → 说明本局没走四结局线，可能在打三结局**：求解之前必须先问
「本局是否打三结局？」；答「要」再问「是否已获取三结局前置收藏品？」，
未获取时把「先行一步」按 15 分必走点处理。**有右区时这道题不适用**（别问、别传参数）。
完整口径与命令见 `26-三层三结局.md`。

## 「无右区」有两个来源（2026-10-30 补充）

1. **四结局前置藏品未获取**（本文件正文）——右区根本不生成；
2. **三结局前置藏品已获取**（玩家 2026-10-30 口径：*获取三结局前置藏品后地图无右区*）。

两条线都不该有右区，看到**左区居中**就是合法局面，不要当成切边反复重截。
三结局线的附带变化：每层有 3 个带徽章的节点（带徽章失与得 / 无效验尸 / 泪之聚落），
见 `27-三结局徽章.md`。

## 识别：看格点宽度，不看「右区节点有没有被 OCR 到」

无右区时左区居中，仍按完整宽度（11/12/14 列）套格点会把列顶出地图区，
尤其 1596 宽的截图。工具（`label_ocr.choose_layer_cols`）会同时拟合：

| 层 | 完整宽度（有右区） | 左区宽度（无右区） |
|---|---|---|
| 三 | 11 列 | 7 列（或 8 列含缝） |
| 四 | 12 列 | 8 列（或 9） |
| 五 | 14 列 | 10 列（或 11） |
| 五·L8 | 13 列 | 9 列（或 10） |

选择依据：格点不越出地图区 + 标签残差 + 格点中心贴近屏幕中心。
选到左区宽度 → `has_right=False`；选到完整宽度 → `has_right=True`。

- **完整宽度但右区一格都没读到** → 这是「截图切边/OCR 漏检」，**报错重截**，
  不许静默当成无右区（否则整层少 3–9 格收益）。
- **左区宽度但玩家说已获取前置藏品** → 矛盾：先核对 Q2/是否拿过前置藏品，再重截。
- `has_right` 会写进 scenario；`route.py` / `build_scenario.py` 都按它决定
  是否拼右区、是否预留 AP、是否检查「右区没进去」。

## 不要用二层 Q2 推断右区

**Q2 问的是「进入二层时是否已获取前置藏品」，不是「本局最终有没有」。**
前置藏品可能在二层过程中才拿到；玩家也可能前两层已经打完，**直接从三层开始对话**，根本没答过 Q2。
所以：

- **Q2=未获取 不能推出**三/四/五层无右区；
- **Q2=已获取 也不能保证**后面一定有右区（可能还没走到/截图没截到）；
- **右区有无只看三/四/五层的实际截图**（完整宽度=有，左区居中=无）；
- 截图/识别拿不准时，**问玩家「本局是否存在熄日余径？」**，再传 `--right-zone 有/无` 兜底。

## 常见错误

| 错误 | 后果 | 正确判据 |
|---|---|---|
| 用二层 Q2=未获取 推断三/四/五层无右区 | 玩家在二层过程中拿到前置藏品，后面右区被整段漏掉 | 以三/四/五层实际截图为准 |
| 未获取前置藏品仍按 11/12/14 列读 | 格点越界/整体错列，起点和构型全错 | 用左区宽度 7/8/10（L8 9） |
| 无右区仍预留 3/4/5 点 | 左区预算被砍，少走 3–5 步 | 无右区时预留=0，整层按左区求解 |
| 无右区仍保留右区必走点 | 必走点永远走不到 → 整层判 ❌ | `derive_must` 只拿 `extra_cells`；无右区时为空 |
| 完整宽度截图但右区没读到，静默当无右区 | 少算右区 6–9 格收益 | 报错「完整宽度但右区空」，先重截 |
| 把无右区当成「截图没截全」反复重截 | 白耗时间；这本来就是合法局面 | 看格点宽度：左区居中=无右区 |

## 实现位置

| 文件 | 作用 |
|---|---|
| `tools/label_ocr.py` | `choose_layer_cols()` 选完整/左区宽度；`has_right_cols()` 判定 |
| `tools/board_read.py` | 输出 `has_right` 与「右区：有/无」 |
| `tools/observe.py` | 识别层后按宽度判右区并打印；`--right-zone 有/无` 兜底并透传给 route.py |
| `tools/route.py` | `has_right` 决定是否拼右区、是否分阶段预留、是否检查「右区没进去」；`--right-zone` 兜底 |
| `tools/build_scenario.py` | 同上；scenario 落 `has_right` |
| `tools/apply_config.py` | 不涉及右区（只覆盖左区定点与险路尽头） |

> 2026-10-30 之前，`route.py` 把「右区一格都没读到」一律判 ❌（当时假设三/四/五层右区必进）。
> 现在改为：**完整宽度才要求右区；左区宽度 = 合法无右区局**。
