# 截图与定价流程（细节）

用户说「我到 X 层了 / 起点 / 理想源 / 加工品…」时，**不要先要截图，先自己抓**：

```bash
python tools/grab.py --scene          # 截图 + 连拍稳定性 + 界面判断 + board_read 节点表
```

> **如果装了 `dsh-plugin-arknights-grab` 插件**（提供 `arknights_grab` 工具），优先直接调它——
> 一个工具调用就能截图 + 判界面 + 出节点表。
> 没装或调用失败时，退回 `python tools/grab.py --scene`（效果相同，只是需要我执行命令）。


判据与后续：

| grab 的输出 | 下一步 |
|---|---|
| `不是战斗地图界面` | **直接告诉用户"现在不在地图界面"**，等他在地图上再说。不要硬分析 |
| `画面在动` | 提示他等动画结束，重跑一次 |
| `像战斗地图` + 节点表 | 定构型 → 更新状态文件 → 按滚动模式给【下一步】 |

**这套动作是强制的**：不用等用户上传图片；他打字就够了。

> 边界：截图只能补"自己看图"。**树根坐标、库存、已探明结果仍以用户口述为准**（见开局报点清单）。


### 层数怎么定：工具从截图里认（2026-10-29 起）

**一次调用就够**：`arknights_grab(scene=true)`（或 `python tools/grab.py --scene`）
会截图 → 标题 OCR 认层 → 按该层网格建格 → 出节点表（类型 / 起点 / 暗「空地」补格）。
输出头一行就是 `层：N（标题「…」）`，照着核对即可。

| 显示名 | 层 | 网格 |
|---|---|---|
| Ⅰ 玻利瓦尔肤层 | **1** | 5×3 |
| Ⅱ 甜美的伤口 | **2** | 5×4 |
| Ⅲ 血色空脉 | **3** | 11×5 |
| Ⅳ 受害者腐殖 | **4** | 12×5 |
| Ⅴ 卡德霍之颅 | **5** | 14×5 |
| i 盲目者所见 | **6** | 5×4 |

**不再需要**「先 grab 一次看标题、再带 layer grab 一次」：`layer` 只在自动认层失败时当兜底。
认不出层时工具**报错**（`!! 认不出层…`），不会偷偷用 11×5 硬读——
一层 5×3 被读成三层 11×5 就是这么来的（见 `19-已知坑.md`「认层只能靠标题/HUD」）。


### 定价是**必做步骤**，不是可选项

拿到「起点 + 构型」之后，**先跑距离表给所有未知格定价，再建场景求解**。
不许凭感觉给「诡秘」一个统一的 4 分——那会漏掉 `狭路相逢/误入奇境` 这类高价值格。

```bash
python tools/expect_by_distance.py <scenario.json> --layer N \
    --revealed "2,2=先行一步,4,2=诡秘" --out dist.txt
```

`--revealed` 填**本层已探明的类型**（截图能读出来的都填）。工具会：

1. 按距离带划掉不可能的类型；
2. 划掉**本层已出现过的一次性类型**（误入奇境/狭路相逢/先行一步/秘境行商/诡意行商）；
3. 若剩下的一次性类型只有一种，打出 `★`，**直接按它估值**。

> 实例（三层 L1）：`(2,2)` 已探明「先行一步」→ `(1,1)` 距离 2 的候选里
> 一次性类型只剩「狭路相逢」→ 该格从 4 分改为 14 分，整层最优解 61 → 71。
> **这一步不跑就会少 10 分。**
## 模拟器分辨率：**固定 1920×864（20:9）**

| 分辨率 | 能否用 | 说明 |
|---|---|---|
| **1920×864（20:9）** | ✅ **唯一推荐** | 14 列能一屏装下；右区不被行动力徽章遮挡 |
| 1600×900（16:9） | ❌ | 三层起右区最右列被行动力徽章压住 |
| 1920×1080（16:9） | ⚠️ 仅一/二/六层 | 同样压右区；且缩放档跨度太大（默认 260、最小 110），中间没有 120 那一档 |

标定基准（1920×864）：14 列 → **sp=120**，11 列 → **sp=124**，5 列（一/二/六层）随缩放变化。
`pixel_probe.set_scale(sp)` 会按 sp 重算白圈徽章的尺寸/偏移窗口，换分辨率不用改代码
（2026-10-30 起只剩这一项；图标裁剪/圆盘常数随 `icon_classify` 类型分类器一并删除）。

> **无右区局**（未获取四结局前置藏品，三/四/五层左区居中）按 7/8/10 列读（L8 9 列），
> 1596 宽也能用；工具会自动判，见 `25-右区有无.md`。
> **三层无右区**判出来之后还有第二步：先问三结局（问题一/问题二），再定价求解，
> 见 `26-三层三结局.md`（先行一步 15 分必走 / 候选坐标）。
## 截图后的标准识别流程（1–6 层统一，2026-10-27 玩家定稿）

**原则：能用文字就不用颜色。** 每个节点下方都写着类型，OCR 的准确率远高于色度规则
（四层实测：色度规则漏检 1/3 且构型无法区分，OCR 读出 29 格、构型一次定死）。

### 五步

```
① 找起点（小人）
② OCR 找 险路尽头（一/二/四层）或 险路恶敌（三/五层）
③ 用「起点 + 尽头/恶敌」定构型 → 格子集合 + 边表
④ OCR 把其余非空地节点全部铺上
④b **用构型的「定点节点」覆盖 OCR 结果**（见下）
⑤ 生成 scenario → 求解
```

### ① 找起点

**小人画在它所在节点的左侧**（不是正上方，也不是节点本身）。
所以：先定位小人的像素坐标，再**往右偏约一格**取其节点。

踩过的坑：曾用「响应最强的峰」当起点，结果小人的高亮压过所有图标，
把起点算到了左边一格。**不要用小人的像素当节点坐标。**

### ② 找尽头 / 恶敌

- **一、二、四层**：文字里找「险路尽头」（1–3 个）；**险路小径**永远不 block
  （险路尽头模式下**一/四层**它也是终点候选；**二层默认小径 0 分、不当终点**，只有尽头能收尾；
  但四结局=不要 或 要且已获取前置藏品时小径=8、可作可选终点，见 `02-地图与险路` 与 `SKILL.md` 〇·〇·一）
- **三、五层**：文字里找「险路恶敌」（1 个）
- **六层**：无险路尽头，有 1 个**险路恶敌**（红骷髅）：
  四结局「盲目者所见」（5×4）全程追猎禁踩、险路尽头模式是本层终点；
  三结局「源流交汇处」（6×5）恶敌固定在 **(3,2)**：全程追猎最后一步必须是**非恶敌**（按墙），
  险路尽头最后一步固定 (3,2)（进入即结束）。OCR 漏检时 `--final c,r` 手报。
  六层有**两张图**（标题分：盲目者所见 / 源流交汇处），不要按单构型处理
  （2026-10-30 更新；旧文「六层只有 1 个构型」已作废）

这些节点**一定会显示文字**（不像普通诡秘那样可能被遮），是可靠的构型锚点。

### ③ 定构型

`起点` 对一、二、六层是**唯一索引**（`17`/`09`/`15` 里有起点→构型表）；
对三、四、五层用「**起点（`起点表.json`）+ 已探明尽头/恶敌坐标**」两把钥匙定构型
（`BS.configs_by_evidence` / `observe.detect_config` 同判据；2026-10-29 勘误：
旧文写的 `tools/offline/grid_fit.py --ref` 格子集合匹配已被 23/SKILL 的钥匙法取代——
集合匹配单独用会认错（四层曾出现 44% 覆盖率的假匹配），只配当并列复核）。

### ④ 铺节点

```bash
python tools/label_ocr.py 截图.png --cols 12 --rows 5 --x0 290 --y0 620 --dx 120 --dy 115
```

- **没文字 = 空地 / 起点 / 汇点**（这几类本来就不写字）→ 记「空地」，价值 0
- OCR 错字用编辑距离校正回词表（`未知的凶房` → `未知的凶戾`）
- 只跑 OCR，**不跑任何色度分类**（2026-10-30 已删除 `icon_classify` 的类型分类：
  四层漏检 1/3、诡秘系一对多）。像素只保留三件事：小人（起点/格点自愈）、
  图标响应（配对/暗空地）、白圈徽章（线人/流窜居民）

### ⑤ 求解

```bash
python tools/route_solver.py scenario.json --max-time 300 --node-limit 120000000
```

**要最优解时必须同时放宽时间与状态上限**：默认 30s / 2000 万状态会中途截断
（四层实测 97 分在 2000 万状态处被截断，无法证明最优）。
### ④b 定点节点覆盖（必须做，否则会算少）

有些节点的类型**根本不写字**，但它在构型表里是**定死**的。OCR 会把它读成「未知的诡秘」或直接漏掉，
必须先按构型查表覆盖：

| 层 | 定点节点 |
|---|---|
| **一层** | 构型1/2：**(3,1) = 诡意行商**；构型3：**(1,2)、(4,1) = 诡意行商**（2026-10-29 修复：构型1 曾漏） |
| 二层 | 索引表「固定节点」列（目前为空，行商位置随局） |
| 三、四层 | **险路尽头/险路恶敌的具体位置必须查构型表**（见下） |
| 五层右区 | 构成固定（2 凶戾 + 3 诡秘 + 1 命运所指），具体格子由 OCR 读 |
| 六层 | **四结局（5×4）**：(0,2)/(4,3) 紧急作战（其一是树根）、(3,3) 行商、(0,3) 不期、(1,3) 得偿；**三结局源流（6×5）**：(1,2) 命运所指、(3,0) 作战、(3,2) 恶敌、(3,4) 不期、(5,2) 行商（起点 (0,2)） |

> **玩家口径（2026-10-27）**：一层所有构型里诡意行商的位置都是固定的，
> **它在地图上确实显示为「未知的诡秘」**——不是 OCR 读错，是这个节点不写标签，
> 玩家本来就要靠「构型 → 定点位置」反推。
> 2026-10-29 起**三个构型的定点都已落进 `apply_config.py` 的表**，
> `route.py` 与 `label_ocr --config X` 会自动覆盖，不用再手改。

**这一步漏做的代价**：一层的诡意行商（+12 源石锭）会被当成普通诡秘（2 分）或空地（0 分）。
2026-10-24 实测过：漏用一次，一层总分从 17 掉到 15。
### ⚠️ 险路尽头会「伪装成诡秘」——必须按构型表覆盖

**2026-10-27 四层实战踩到**：L6 的尽头集是 `(0,4)(3,1)(7,2)`，其中
`(0,4)` 和 `(7,2)` 的标签真的写着「险路尽头」，但 **(3,1) 的标签写的是「未知的诡秘」**。
我按 OCR 结果把 (3,1) 当成普通诡秘（5 分）铺进场景，求解器于是把「走进 (3,1)」当成第一步——
**实际那是禁踩的尽头**。

规则：
- **四层没有险路恶敌，只有 3 个险路尽头**（`11-四层左区构型` 末尾有逐构型的尽头表）
- 它们**不一定显示为「险路尽头」**，可能伪装成「未知的诡秘」
- 所以 **④b 必须无条件用构型表的尽头坐标覆盖 OCR 结果**
- 同理：一层「只点亮 1 个尽头，其余伪装」（`17-一层构型`）

> 一句话：**标签只能告诉你「这里有个节点」，不能告诉你「它是不是尽头」。尽头的身份由构型表决定。**
### ④c 流窜居民 → 反推居民据点（有徽章时必须做）

四层起会出现「流窜居民」：**白色小圆圈徽章叠在林间空地上**，中心在格子右上方约 30px。
它们是据点的产物，**初始生成在距据点 ≤5 步的空地上**，所以可以反推：

```
据点 ∈ { 到每一只居民都 ≤5 步 } ∩ { 未知的凶戾 }
```

工具：
```bash
python tools/resident_infer.py scenario.json --residents "2,2;6,2;7,0"
```

**2026-10-27 四层实测**：居民 `(2,2)(6,2)(7,0)` → 距离约束后仅 4 格候选 → 与凶戾求交 →
**唯一 = (4,0)**（到三只居民分别 4/4/3 步）。

**居民据点收益 = 10**（玩家口径 2026-10-27）。

徽章检测注意：
- 用**白块检测**（`pixel_probe.detect_residents`），不要用色度阈值
- 徽章在格子**右上方**，不在格心
- **必须落在空地上**才算居民；落在不期而遇上的是**线人**（二结局事件），不是居民
### ④d 诡秘池候选清单（三/四/五层必跑，2026-10-27 玩家要求）

「未知的诡秘」不是同质的。用 `06-距离表` 的距离带可以把一部分格子**排除**掉某些类型：

| 类型 | 三层 | 四层 | 五层 |
|---|---|---|---|
| **狭路相逢** | 2–4 | 2–10+ | 2–4 |
| **秘境行商** | 3–6 | 2–6 | 2–10+ |
| **误入奇境** | 5–6 | 5–8 | 3–8 |

```bash
python tools/pool_candidates.py scenario.json --layer 5 --route "5,3;2,3;3,3;..."
```

**输出要求（给玩家看的格式）**：

1. 进三/四/五层、给出路线时，**附一张小型候选表**：哪些诡秘格可能是这三种之一，按距起点步数排序
2. **如果路线经过的某个诡秘格在候选表里，必须在路线那一步标注**，例如
   `(4,3) 未知的诡秘 ← 可能是狭路相逢/秘境行商/误入奇境`
3. 目的：让玩家判断「这一格值不值得多花 1 步去探」——狭路相逢和误入奇境都是 10 分，秘境行商能买东西
### ④a 格点校验：用「图标位置」验列距（防整体错一列）

**现象**：列距被估偏后，前几列还对得上，越往后偏得越多，
于是 `(1,1)` 被读成 `(2,1)`——**整列错位**，路线看着通顺但落点全错。

**为什么只看标签发现不了**：标签本来就是按这个（错的）格点聚类出来的，自洽。

**做法**：每个标签正上方都有一个图标，**图标位置才是节点的真实坐标**。
工具会自动比对并打印：

```
格点校验 ✅ 图标残差 中位 2.5px / 最大 17.5px / 超差 0/12（阈值 中位≤18px、超差≤20%）
```

判据分开处理两种失败：

| 情形 | 表现 | 结论 |
|---|---|---|
| **整体拉偏** | 中位数就大；大多数标签超差 | ❌ 列号不可信 → **重截再跑**（⛔ 禁止手传 `--x0/--dx` 自救，见 23-操作流程；格点只许取工具自标定的输出） |
| **个别噪点** | 中位数正常；只有一两个超差 | ✅ 可接受（图标峰值抓歪） |

实测（二层 1920×864）：正确格点 `dx=121` → 中位 2.5px ✅；
把 `dx` 故意估成 100 → 中位 37.5px、8/12 超差 ❌；
估成 140 → 中位 35.5px、6/12 超差 ❌。

**注意**：容差必须按 `dx` 的比例算，不能按绝对值——否则 `dx` 估大时容差也跟着变大，
反而放过了错误（第一版就栽在这：`0.45×dx` 让 `dx=140` 被判为通过）。
### ④e 两类「看起来像数据、其实不是」的输入

| 输入 | 能用来干什么 | **不能**用来干什么 |
|---|---|---|
| **「实战固化」表** | 读结构：上链/下链、死端、主环路 | 断言某格是诡秘/凶戾/空地 |
| **图标形态**（肺/胚胎/兽首） | 仅在 OCR 完全失效时兜底，且必须显式声明不可靠 | 判节点类型 |

**为什么图标形态不行**：它对应的是**一类**，不是一个类型。

| 图标 | 可能对应 |
|---|---|
| 肺 | 未知的凶戾 **/** 紧急作战 |
| 胚胎系 | 未知的诡秘 **/** 不期而遇 **/** 得偿所愿 **/** 安全的角落 |
| 兽首 | 作战 **/** 紧急作战 |

而文字标签是**唯一的**类型区分手段。2026-10-27 有会话放弃 OCR、改用图标形态判类型，
把「未知的凶戾」和「紧急作战」混为一谈，进而把 9 分和池内期望算错。

**判据：文字标签 > 一切视觉推断。**
