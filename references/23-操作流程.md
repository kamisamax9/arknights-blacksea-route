# 操作流程（强制步骤，逐步照做）

> 本文件由 SKILL.md 的「〇·六」整段迁出——SKILL.md 只保留心智模型与入口，
> 具体命令、参数、校验项全部下沉到这里，避免主文件臃肿。

## 每次规划前的固定动作（强制；识别一律先 OCR）

0. **⭐ 截图源纪律（2026-10-29 事故后置顶，先看这条）**

   事故：`observe.py` 当时把 adb 路径写死，抓图失败后执行方**去翻 `runs/shots/` 里的旧截图**，
   把上一局「血色空脉」三层的画面当成当前局来规划。识别没错，**输入源取错**，所以现在有三道机械闸：

   | 闸 | 行为 | 想绕过时 |
   |---|---|---|
   | **adb 自动发现**（`tools/adb_find.py`） | `--adb` → 环境变量 `ARKNIGHTS_ADB` → 上次成功缓存 → 常见安装路径/通配 → PATH；设备为空自动 `adb connect` 常见端口；找不到就**列全试过的地方** | 先跑 `python tools/observe.py --probe` 看报告；真要指路就 `--adb <路径>` |
   | **旧图闸**（observe.py） | `--image` 超 5 分钟、或 `runs/shots` 里有明显更新的一张 → **拒绝**，并列出最新那张与处置顺序 | 只有复盘用 `--allow-stale`，且结论必须标「基于旧图」 |
   | **地图闸**（observe.py） | 画面不是树海地图（战斗/结算/主菜单）→ 直接报错，不硬分析 | 确认是配色异常才 `--no-map-check` |

   ⛔ 抓图失败时**禁止**改用 `runs/shots/` 里的旧图（别的对局/别的层）。
   处置顺序：① 重跑 → ② `--adb` 指路 / `--device` 换设备 → ③ 让玩家现场截图后 `--image`（必须是刚截的）。

0.5 **⭐ 环境自检（2026-10-30 事故后新增，先于一切命令）**

   ```bash
   python tools/pyenv.py          # 当前解释器 + 依赖；缺时列出本机齐全的解释器 + 可复制命令
   ```

   ⛔ **`pip` 的 Python ≠ 跑脚本的 Python**：`pip install` 全「Requirement already satisfied」
   不代表跑脚本的那个解释器能 import。报「缺依赖」之前，**先看 `pyenv.py` 打印的解释器路径**。
   - 缺 OCR（`rapidocr_onnxruntime`/`onnxruntime`）→ `label_ocr` 会打印「本解释器：…」+ 本机可用解释器；
   - 缺 `scipy` → 滚动阶段「站在带标签节点上」判定会**打 ⚠️ 降级**（不再静默），
     `selftest_lattice` 10/11 按跳过计。

1. **截图** — 调 `arknights_grab`（装了插件）或 `python tools/grab.py --scene`。
   输出「不是战斗地图界面」→ 直接告诉用户，别硬分析；「画面在动」→ 等他等动画结束再截。
   ⛔ **截图不是地图（零件箱/干员/结算/主界面）时，只报告，绝对不要用 adb 点按钮去关掉它。**
   2026-10-26 四层：我连点「收起」「左上返回」，直接把对局退到树海主界面，多花 73s + 3 次截图才回图。
   截屏只用来**看**，不用来**操作**——要关界面，请玩家自己关。
2. **定层** — **工具自己认，不要先问玩家/先传 layer**：`arknights_grab`（或 `grab.py --scene`）
   截图后会跑 `board_read.py`，从标题区 OCR 认层并在输出里打 `层：N（标题「…」）`。
   标题对照：`Ⅰ玻利瓦尔肤层=1 · Ⅱ甜美的伤口=2 · Ⅲ血色空脉=3 · Ⅳ受害者腐殖=4 · Ⅴ卡德霍之颅=5 · i盲目者所见=6`；
   网格随之定为 1:5×3 / 2:5×4 / 3:11×5 / 4:12×5 / 5:14×5 / 6:5×4。
   **认不出层时工具报错**（`!! 认不出层…`）——这时才看 `*_title.png` 人工核对，
   或用 `--layer N` 兜底；⛔ 不许在没认层的情况下拿默认 11×5 硬读（2026-10-29 一层就是这么读错的）。
2.5 **⭐ 二层必问：四结局（2026-10-30 新增，强制；在求解之前）**

   `observe.py` / 标题 OCR 认出**二层**（或玩家直接报二层）后，**先问玩家再跑命令**：

   | 终点模式 | 问什么 | 分支 → 参数 |
   |---|---|---|
   | 全程追猎 | Q1 本局是否要打四结局？ | 要 → 尽头 8、走 1 次 → `--four-ending 要`；不要 → 尽头 0、不必走 → `--four-ending 不要` |
   | 险路尽头 | Q1 同上；答「要」再问 Q2 是否已获取四结局前置藏品？ | Q1 不要 → 小径=尽头（8）、可作可选终点 → `--four-ending 不要`；Q1 要 + 已获取 → 同上 → `--four-ending 要 --four-ending-pre 已获取`；Q1 要 + 未获取 → 小径 0、不作终点，终点=尽头 → `--four-ending 要 --four-ending-pre 未获取` |

   ⛔ **没问完就调工具，二层会直接 ❌（exit 2）**，不会先算一版。报错会写明缺 Q1 还是 Q2。
   同一局二层滚动重算沿用答案（scenario 里的 `four_ending` / `four_ending_pre`），不必重复问。

2.5.1 **三/四/五层：先判右区有无（2026-10-30）**

   `observe.py` / `board_read.py` 会按格点宽度打印「右区：有/无」：
   - **无右区**（本层无熄日余径，左区居中）：不预留 AP、右区必走点/收益/配额全部失效，
     整层按左区求解；不许再报「右区没进去」。
   - **有右区**：按原流程分阶段/整体求解；完整宽度但右区一格没读到 → 先重截，别静默当无右区。
   - **不要用二层 Q2 推断**：Q2 问的是进入二层时是否已获取前置藏品；前置藏品可能在二层过程中
     才拿到，玩家也可能直接从三层开始对话。右区有无以三/四/五层实际截图为准；拿不准就问玩家
     「本局是否存在熄日余径？」再传 `--right-zone 有/无`。
   详则 `references/25-右区有无.md`。

2.5.2 **三层：无右区必问三结局（2026-10-30 新增，强制；在求解之前）**

   三层**没有右区**（2.5.1 判为「无」，熄日余径不存在）时，**先问玩家再跑命令**：

   - Q1「本局是否打三结局？」→ **不要** = 普通逻辑 → `--three-ending 不要`
   - Q1 **要** → Q2「是否已获取三结局前置收藏品？」
     - **已获取** = 普通逻辑 → `--three-ending 要 --three-ending-pre 已获取`
     - **未获取** → **「先行一步」按 15 分必走点**：已探明就锁坐标；还藏在未知诡秘里就
       列出候选坐标（距**层起点** 2–4 步）并让玩家去这些格子找
       → `--three-ending 要 --three-ending-pre 未获取`
   - **有右区时这道题不适用**（有右区 = 走四结局线），别问、也别传参数。

   ⛔ 没问完就调工具，三层会直接 ❌（exit 2），不会先算一版。
   同一局三层滚动重算沿用答案（scenario 里的 `three_ending` / `three_ending_pre`）。
   详则 `references/26-三层三结局.md`。

2.6 **⭐ 标准入口：一条命令，一个判词**

   ```bash
   python tools/route.py 截图 --layer N --config 构型 --ap N
   # 二层再加（必答；险路尽头模式答「要」还要 Q2）：
   #   --four-ending 要|不要 [--four-ending-pre 已获取|未获取]
   # 三层（仅无右区）再加（必答；答「要」还要 Q2）：
   #   --three-ending 要|不要 [--three-ending-pre 已获取|未获取]
   # 玩家核过图上标注（节点标签）→ 判词「输 入」里升为「事实」：
   #   --labels-confirmed
   ```

   它一次做完：读图 → 起点 → 构型校验 → 定点覆盖 → 建场景 → 求解 → **全部校验**，
   最后只给一行判词（**四态**，2026-11-02）：

   ```
   ✅ 可用（在本场景模型内已证最优；N 项输入待确认）   exit 0
   ⚠️ 有条件可用（N 项风险…）                        exit 0
   ⏳ 未定（搜索没跑完，不能判定无解）                 exit 4
   ❌ 不可用：<原因>                                  exit 3
   ```

   **执行方不需要理解任何细节**——`✅` 才可以把路线交给玩家；`⚠️` 要连「风 险」栏一起转达；
   `❌` 按列出的原因改参数重跑；`⏳` **不是**「没有路线」，是「这次没搜完」，加大 `--max-time`
   （或 `--joint` / 放宽约束）重跑，**禁止**自己补一条路线，也禁止说成「无解」。

   判词上方另有两行同样要转达：`求解口径：`（计算状态 OPTIMAL/FEASIBLE/INFEASIBLE/UNKNOWN）
   与 `输　　入：`（事实/推断/待确认/期望）——**有「待确认」项时，`✅` 只等于「在这张图里已证最优」**。

   它内置的校验（任一不过即整体 ❌）：

   | 校验 | 不过的样子 |
   |---|---|
   | 起点 vs 构型 | `起点不符：检测 (2,1)，构型2 应为 (1,1)` |
   | 格子必须在构型内 | `读到构型外的格子 [(0,0),(4,2)]` |
   | grants 白名单 | `grants 非法：(3,0)=安全的角落` |
   | AP 收支平衡 | `AP 收支不平：预算 7，实走 6` |
   | 回头步必要/可避免 | `存在可避免的回头步：第2步(2,1)` |
   | 求解未截断 | `撞到时间/节点上限` |

   **下面的手工步骤只在 `route.py` 跑不起来时才用。**
3. **定起点 + 定构型（标准流程：起点与已探明尽头/恶敌坐标一起定构型，差分只复核）**

   ⛔ **起点节点本身没有标签**（它是空地），OCR 只会读到 `∅`——所以必须靠**小人**来定位。

   ```bash
   python tools/label_ocr.py 截图 --cols N --rows M --layer N
   ```

   输出的**第一行**就是起点（`★ 起点（自动检测）：(c,r)`）。检测不到时工具会写明
   「**未检测到小人** → 必须问玩家」，这时**禁止猜**，直接问玩家。

   玩家口报时用 `--start c,r` 覆盖：

   ```bash
   python tools/label_ocr.py 截图 --cols 5 --rows 4 --layer 2 --start 0,0
   ```

   **构型 = 起点 × 尽头/恶敌 两把钥匙（玩家 2026-10-28 定死，observe.py 已内置此优先级）**：
   ① 层数由标题 OCR 定（唯一权威）；② 起点候选 + 屏上「险路尽头/险路恶敌」标签吸附格点
   → `BS.configs_by_evidence` 硬过滤（观察到的地标必须全部落在构型声明集合里）；
   ③ 节点集合求差**只作并列复核**。

   - **为什么地标必须从全图 OCR 标签直接捕获**：尽头球大、标签比普通格低 50+px，
     节点检测的吸附容差会把它丢掉（2026-10-28 二层 (4,1) 漏检 → 地标钥匙空转）。
   - **为什么差分不可为主**：进层初期大多数据格未点亮，二层 19 格只亮 10 格时，
     差分把构型7 推上首位、反把屏上真尽头 (4,1) 无视（2026-10-28 实测翻车）。
     **钥匙与差分冲突时，一律以钥匙为准。**
   - 二层构型 1/2/3/7 的**格子集合完全相同**（自检都零越界），只有起点不同
     （(0,0)/(1,0)/(1,1)/(4,0)）。2026-10-27 就有会话把起点 (0,0) 读成 (1,1)，
     于是把**构型1 判成了构型3**——这正是差分不配当主判据的另一例证。

   定完起点与构型再往下走。

   3.1 **屏上有「流窜的居民」（无文字小图标）→ 必跑 `resident_infer.py`（2026-10-28 四层漏推教训）**

   流窜居民**没有文字标签，OCR 看不见**——必须人眼扫图或玩家口报坐标。
   居民出现 ⇒ 本层必有**居民据点**；据点 = {到每只居民 ≤5 步} ∩ {未知的凶戾}：

   ```bash
   python tools/resident_infer.py 场景.json --residents "0,2;1,1;5,1" --maxdist 5
   ```

   唯一确定时立即锁类型并**连锁更新配额推断**：据点占掉一个未知凶戾后，
   剩余未知凶戾按「紧急作战还差几个」重新分配（四层实例：据点 (3,1) 锁定后，
   (2,4) 由 4.5 期望变**紧急作战 9 分确定值**——总收益差 7 分，路线整个反转）。

   3.2 **三/四层先清左区再进右区（玩家 2026-10-28 规则；仅当本层有右区）**

   > **无右区**（见 2.5.1 / 25 号文件）→ 本段整段跳过：没有右区可进，整层按左区求解，
   > 不预留 AP、不排右区必走点。

   右区作战高一档：**三层右区 = 四层的作战，四层右区 = 五层的作战**（五层右区 = 五层同档，不受此限）。
   先清左区养收藏品/等级，再进右区打高一档的仗。

   实现：场景 JSON 加两个键后交给 `route_solver.py` 穷举（不要手推顺序——手推必困死）：

   ```json
   "left_first": true, "right_from_x": 9
   ```

   `right_from_x` = 右区首列（三层 8、四层 9、五层 11 / L8 变体 10）。
   求解器语义：**踩过右区格之后就不再踩左区价值格**（纯过境不限）。
   四层实测：左先约束下仍达全局最优 116.1（行商最先、气垫留作右区内部跨越——
   这个顺序手推三轮全困死，穷举一次找到，见 19-已知坑「手推邻接必错」）。

3.3 **改动求解器后的强制回归（两条，缺一不可）**

   ```bash
   python tools/selftest_solver.py    # 行为断言：修复有没有被改回去
   python tools/regress.py --quick    # 0.2s：迷你场景冒烟（改代码时**每轮**都跑）
   python tools/regress.py            # 50s：全量（**收尾跑一次**就够）
   ```

   ⛔ **别拿全量回归当迭代工具。** 2026-10-28 我调性能时连跑 6 次全量回归（每次约 50s，
   合计约 6 分钟），占那一轮总耗时一半以上。正确节奏：
   **调 → `selftest` + `regress --quick`（合计 0.3s）→ 定稿 → 全量一次。**

   **为什么光跑分数不够**：有些修复只在特定输入下显形（2026-10-27 有会话只靠「分数还是 73」
   判断撤回无伤，但「道具等价类按价格分组」这类修复在小场景里分数可能碰巧不变）。
   四项断言各抓一类：分数=结果变了；**步数**=同分不同路；**未截断**=没搜完却报对分数；
   **定价指纹**=定价表变了、期望值可能**合法**变化（会提示复核，复核后 `--accept-pricing` 更新）。
3.4 **定点覆盖：用构型表改写「看起来对、其实是伪装」的格子**（必做，工具已内置）

   每一层的构型表都规定了一些格子**必须是什么类型**，而地图上显示的是伪装名：

   | 层 | 伪装 | 实际 |
   |---|---|---|
   | 一层 | `(0,0)` 显示「未知的诡秘」 | **险路尽头**（两个尽头只点亮一个） |
   | 一层 | `(1,2)`/`(4,1)` 显示「未知的诡秘」 | **诡意行商**（定点，不参与随机） |
   | 四层 | L6 的 `(3,1)` 显示「未知的诡秘」 | **险路尽头** |

   ⛔ **「格子都在边表内」不等于「类型都对」。** 这一步是独立的，必须单独做。

   2026-10-27 就有会话只核对了「所有格子都在边表内」，然后报告
   「`(0,0)` 没有绘制节点」——实际上那里有节点，只是写着「未知的诡秘」、
   是**伪装成诡秘的险路尽头**。若照它的判断走，求解器会认为 `(0,0)` 可以进去拿 2 分。

   `route.py` / `label_ocr.py --layer N --config X` 会自动覆盖并打印：

   ```
   定点覆盖：(0, 0)=险路尽头、(1, 2)=诡意行商、(4, 1)=诡意行商、(4, 2)=险路尽头
   ```

   看到这一行才算做了覆盖；**没有这一行就说明没做**。
3.5 **建场景：一条命令，禁止手抄**

   ```bash
   python tools/build_scenario.py 截图 --layer N --config 构型 --ap N
   # 二层同样必答 --four-ending（及险路尽头模式下的 --four-ending-pre）；
   # 不给答案会直接报错，不会生成一版旧口径 scenario。
   ```

   它把「读图 → 自标定 → 起点 → 定点覆盖 → 查边表 → 定价 → 写 json」一次做完，
   **中间不经过人手**。输出就是 `runs/L{层}-c{构型}-{HHMM}.json`。

   ⛔ **禁止把 OCR 的表格手抄进 scenario。** 2026-10-27 一天内因此出了三次事故：
   - 把 `(1,2)` 抄成 `(1,1)` → 占掉了原来 `(1,1)` 的凶戾 → 凶戾被挤到 `(0,1)` → 还漏了两个定点；
     而且**表格和同一段正文自相矛盾**（正文写 (1,2)，表格写 (1,1)），没有任何检查会发现
   - 抄边表漏 1 条（19→18）→ 断言「(2,2) 是孤点」

   **只要「识别结果」到「求解输入」之间有一次人工转录，这类错误就一定会发生。**

3.6 **滚动重算：`--visited` 与「起点 = 当前所在格」**（2026-10-29 新增，必读）

   进层之后每重算一次，都必须把**已经走过的格**报给求解器：

   ```bash
   python tools/route.py 截图 --layer 3 --config L1 \
       --start 6,3 --ap 8 --visited "0,2;6,3" --root 6,3 \
       --items "报废轮子:2;结构性原理:1"
   ```

   | 参数 | 滚动时的含义 | 不这么做的后果（实测） |
   |---|---|---|
   | `--start` | **玩家当前所在格**（不是进层起点） | 拿进层起点算，已走过的树根会被当成没走过 |
   | `--visited` | 已经走过 / 已触发过的格 | 树根再计 15 分、再发 +2 AP |
   | `--root` | **仍然要传**（树根坐标只能人报）；`--visited` 只抽掉它的 +2 | 不传 → 该格无标签被读成「空地」，**紧急作战配额账目丢失**，(1,3) 从 0 分被抬到 9.0 分 |

   三条实现口径（改代码前先读 `route.py` 的 `apply_visited` docstring）：

   1. **`--visited` 只抽 grant，绝不改节点类型**——树根本身就是那场紧急作战，
      改成「起点」会让配额推断以为「还差 1 个紧急」，把 0 分的凶戾抬成 9 分。
   2. **visited 格要自动摘出 `must`**（已经打过，不该再要求走一遍，否则必然判「必走点走不到」）。
   3. **滚动模式禁止写 `起点表.json`**（当前位置不是进层起点，写进去会污染后续构型识别）。

   `--ap` 报**当前余额**（已含已领的 +2）；尚未走到的羽瞰点等 grant 仍由工具自动补进预算。

   ⛔ **当前位置以玩家口报为准，截图只是佐证。** 2026-10-29 事故：玩家在 (2,4) 秘境行商，
   `grab --scene` 报 (3,3)（小人检测把「站在带标签节点上」误判了），执行方拿图覆盖了玩家原话，
   排出整条错路线。现已修：`label_ocr` 用「暖色块是否**全部**被标签规则剔除」判别
   「玩家正站在带标签节点上」，命中时不再用「起点不写字」这条罚则；`observe.py` 命中时直接
   停下并提示改用 `route.py`（详见 `19-已知坑`）。

   **两个命令行，别混用**：进层那一刻用 `observe.py`；之后每一步用 `route.py --start/--visited`。

4. **读格子内容 → 一律先跑 OCR，不要先跑色度**

   ⛔ **「格子少」不是跳过的理由。** 一层 5×3 看起来最简单，实际最容易读错：
   图标大、标签离节点 **85px**（老代码的偏移上限只给 70px，整排标签会丢）、
   而且**伪装节点最多**——构型3 的 (4,2) 是伪装的险路尽头、(1,2)(4,1) 是定点的诡意行商，
   图上全都写「未知的诡秘」。2026-10-27 我就因为「5×3 很小、肉眼看得了」跳过 OCR，
   改用 `read_scene` 找圆点 + 自己看大图，结果整行错位（(3,1) 读成空地、(3,0) 读成诡秘）。

   ⛔ **不要退回「找可见圆点」**：圆点是汇点不是节点，不能当坐标来源。
   `read_scene.py` 的旧命令行（干的就是这件事）**2026-10-30 已删除**，现在是纯库
   （`response_map` / `fit_lattice`），只能被工具 import，不该被拿去读坐标。

   ⛔ **构型匹配失败 = 你读错了，不是「这局没构型」。**
   一~六层**每一层都必然对应某一条构型边表**。如果格子集合对不上任何一条，
   唯一正确的动作是**重新标定、重读**，绝对不允许改口成「按图上看到的连通关系来推」。

   2026-10-27 就出过这种事：某次读数把行数当成 5 行（一层其实是 3 行），
   于是「对不上任何构型」，然后它宣布「按我确认的连通关系算」——
   **拿像素猜边表，是整个流程里最不可靠的数据**（见 `19-已知坑` 第 3 条）。

   校验方法（构型3 实测）：
   ```
   构型1 ❌ 2 格越界 [(0,0),(4,1)]
   构型2 ❌ 2 格越界 [(0,0),(4,2)]
   构型3 ✅ 全部在构型内      ← 唯一正确解
   ```

   ```bash
   python tools/label_ocr.py 截图 --cols N --rows M --layer N --config 构型
   ```

   **带上 `--layer N --config 构型` 时，工具会把定点节点直接覆盖并标 `(定点)`。**
   输出里的 `(定点)` 就是**最终类型**——不要再去和 OCR 文字比对，也不要自己判断「谁优先」。
   典型冲突：一层 (4,1) 地图上写「未知的诡秘」，构型3 规定它是**诡意行商**，
   输出会直接写 `4:诡意行商(定点)`；四层的伪装尽头同理，写成 `险路尽头(定点)`。

   ⛔ **不要传 `--x0/--dx/--y0/--dy`。** 工具会**从标签位置自标定**格点
   （每个节点下面都有字，标签的 x/y 就是列/行中心），并能补上「一个标签都没有」的列
   ——五层的接缝列就是这种。维度也会自纠：传 14 列但实际 13 列时，它会报「按自标定结果处理」。

   ⛔ **节点类型只认文字标签。** 不要用图标形态判类型：
   「肺=凶戾、胚胎=诡秘、兽首=作战」这类经验规则**会错**，因为图标对应的是**一类**而不是一个类型——
   肺既可能是「未知的凶戾」也可能是「紧急作战」；胚胎系图标覆盖诡秘/不期而遇/得偿所愿/安全的角落；
   兽首既可能是「作战」也可能是「紧急作战」。**文字标签才区分得开。**

   ⛔ **「实战固化」表只用来读结构**（哪条是上链、哪里有死端），
   **绝不能用来断言某格是什么节点**——那是某一局的快照，跨局不变的只有边表和定点行商。
   标签与固化表冲突时，**永远信标签**。

   ⛔ **类型只认文字。** 旧的色度分类（`icon_classify`）**2026-10-30 已删除**：
   四层深青「未知的诡秘」漏检 1/3，诡秘系图标一对多，凶戾与紧急作战同族。
   OCR 跑不起来时**问玩家**，不要退回色度猜类型。像素现在只剩三件事：
   小人（起点/整列自愈）、图标响应（配对/暗空地）、白圈徽章（泪之聚落/线人/迷藏等 6 种，见 `27`）。
   色度对四层的深青「未知的诡秘」几乎无效（漏检 1/3，还会把暗背景判成险路尽头）。

   读完必须再做两步覆盖，否则路线一定错：

   ```bash
   python tools/apply_config.py scenario.json --layer N --config 构型 [--end-mode 险路尽头] \
       [--four-ending 要|不要] [--four-ending-pre 已获取|未获取] \
       [--three-ending 要|不要] [--three-ending-pre 已获取|未获取]
   ```

   - 把该构型的**险路尽头全部改成禁踩**（**险路尽头模式下例外**：一/四层尽头不再 block、
     与小径同分值，`final_type=["险路尽头","险路小径"]`；**二层默认只有尽头是终点**（8 分，小径 0 分）；
     但四结局=不要 或 已获取前置藏品时，`final_type` 追加小径、双 8 分；三/五/六层恶敌同理）——它们可能伪装成「未知的诡秘」，OCR 看不出来
   - 把**固定节点**改成真实类型（一层：构型2 (3,1)；构型3 (1,2)(4,1) = 诡意行商）
   - 二层的四结局答案从命令行或 scenario 的 `four_ending` / `four_ending_pre` 读；旧 scenario 没写则按旧口径（要+未获取）兜底
   - 三层（无右区）的三结局答案从命令行或 scenario 读；要+未获取时把「先行一步」写成 15 分，
     已探明的坐标补进 `must`（还藏着时用 `pool_candidates.py --layer 3 --xianxing` 列候选）
   - **白圈徽章**由 `board_read` / `route.py` / `build_scenario.py` 自动读（不用手加参数），
     按**字形**认：骷髅=泪之聚落（**0 分**、默认不进、可过路）、蜘蛛=线人、羊角=三结局失与得、
     狼头=无效验尸（后两者**不改价**）、**橡果=迷藏**（**所在节点 +12 分**，带橡果的空地放行）、
      乌鸦=流窜居民。
     详见 `27-三结局徽章.md`

   再跑 `tools/pool_candidates.py` 列出诡秘里的高价值候选（狭路相逢/秘境行商/误入奇境）。
4. **定价** — `tools/infer.py` + `tools/expect_by_distance.py`：给每个未知格算候选与期望。
   **不许给「诡秘」一个统一分**，那会漏掉狭路相逢/误入奇境这类高价值格。
5. **求解** — 建 scenario → `tools/solve_scan.py`（升序预算扫描，**达可采纳上界才算证明**）。
   ⛔ **「相邻两档同分」≠ 到顶**（2026-11-02 纠正：单调性只给 `best(k+1) ≥ best(k)`，
   完全可能 20 / 20 / 30）。`solve_scan.py` 只在**分数摸到可采纳全局上界**时收工；
   同分只算**启发式**，会明说「未证明、还差多少」，`--strict` 时干脆不信同分。
   2026-10-26 四层：「原理4次」跑了 75 秒撞到 2000 万状态上限，结果与「1 次」同为 89
   ——那是**撞上限**，不是「已证到顶」。
   要证明就 `--strict` 扫满；要省时间就用启发式结果，但**不许把同分说成已证最优**。
