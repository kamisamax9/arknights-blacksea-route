# 三层「三结局」问询（2026-10-30 玩家新增，**仅无右区时强制**）

## 什么时候问

**三层**（玩家口报，或截图 / `observe.py` 标题 OCR 识别到三层，都算）**且本层没有右区（熄日余径）**时，
在求解之前必须先问。

- **有右区 = 本局走的是四结局线**（右区只在该前置藏品已获取时出现，见 `25-右区有无.md`）
  → 这道题**不适用**：别问，也别传参数（传了工具按「用错」报错）。
- **无右区**（左区居中、格点 7/8 列）→ **必问**。没问就调 `route.py` / `observe.py` /
  `build_scenario.py`，工具直接 `❌ exit 2`，不会先按旧口径算一版。
- 同一局三层的**滚动重算沿用答案**（scenario 里的 `three_ending` / `three_ending_pre`），
  不必重复问；换了新对局/新三层要重新问。

## 问什么、怎么定价

> **问题一：本局是否打三结局？**

| 回答 | 后续 | 参数 |
|---|---|---|
| **否** | 按普通逻辑规划（先行一步仍 2 分、不必走） | `--three-ending 不要` |
| **是** | 继续问问题二 | `--three-ending 要` |

> **问题二：是否已获取三结局前置收藏品？**

| 回答 | 三层「先行一步」 | 参数 |
|---|---|---|
| **是** | 按普通逻辑（已经拿到了，不必再找）；但**每层有 3 个带徽章节点**：失与得/无效验尸**不改价**、泪之聚落 **0 分**（见 `27-三结局徽章.md`） | `--three-ending-pre 已获取` |
| **否** | **15 分 + 必走点**：已探明就锁坐标；藏在未知诡秘里就列候选坐标去找 | `--three-ending-pre 未获取` |

> 前置收藏品就是**三层进入「先行一步」拿到的那个**。三层左区**必有 1 个先行一步**
> （`04-推演规则` 数量表），还没见到它，它就一定在剩余「未知的诡秘」里。

## 「先行一步」怎么处理（Q1=是、Q2=否）

1. **已探明**（OCR 读到，或玩家口报「先行一步」在某格）：
   - `values["先行一步"] = 15`（`rules.THREE_XIANXING_VALUE`）；
   - 坐标写进 `must`（硬约束：漏走不收解，走不到会如实报 ❌）。
2. **还没探明**（藏在「未知的诡秘」里）：
   - 仍然按 15 分给 `values["先行一步"]`——所有候选格的诡秘**期望值会随之抬高**；
   - **列出所有候选坐标**（`06-距离表`：三层的先行一步只可能在距**层起点**徒步 **2–4 步**的格子；
     不是距当前位置，见 `19-已知坑`）：
     类型是「未知的诡秘」、在左区、且不在已走格（visited）里；
   - 输出会写成：
     ```
     ⚠️ 三结局：先行一步还没探明，可能藏在这些「未知的诡秘」里（距离带 2–4）：
        (0,2) 距2步、(1,2) 距3步、(1,1) 距4步
        → 请在这 3 个坐标里找「先行一步」；进去就拿到三结局前置收藏品（找到后按新截图重算）
     ```
   - **提示玩家去这些坐标找**。一个候选都没有时工具会如实说「本层找不到它」，
     让玩家核对截图（漏检）或已走格（可能已经走过）。
   - 路线一格候选都不经过时，判词会补一条 ⚠️：拿不到前置收藏品（不升级 ❌——
     玩家可能打算下一步再去，或候选本身是 OCR 漏检）。

> 候选只有 1 格时输出会提示「只剩这一格 → 它就是先行一步」——这是 `04` 数量表的机械推论，
> 但**不会自动写成必走点**（可能是 OCR 漏检，也可能那一格其实已经走过）。

## 命令

```bash
# 三层 · 无右区 · 不打三结局（普通逻辑）
python tools/route.py 截图 --layer 3 --config L1 --ap 6 \
    --three-ending 不要 --items "标准引擎:1"

# 三层 · 无右区 · 打三结局、前置收藏品还没拿到（先行一步 15 分必走；藏着就列候选）
python tools/observe.py --three-ending 要 --three-ending-pre 未获取 --explain

# 滚动重算沿用答案（三层）
python tools/route.py 截图 --layer 3 --config L1 --start 2,2 --ap 5 \
    --visited "0,2;1,2" --three-ending 要 --three-ending-pre 未获取 --items "标准引擎:1"

# 手工 scenario：只列先行一步候选坐标
python tools/pool_candidates.py runs/L3-cL1-1535.json --layer 3 --xianxing
```

## 未回答 / 用错层的兜底

- 三层无右区、缺 Q1 → `route.py` / `observe.py` / `build_scenario.py` **exit 2**；
- 答「要」但缺 Q2 → 同样 exit 2（报错写明缺的是 Q2）；
- **有右区**却传了 `--three-ending` → 报错（这道题只属于无右区局）；
- **非三层**传 `--three-ending` → 报错（`layer3_scope_errors`，读图之前就挡，
  防止把答案串到别的层）；
- 旧 scenario 没有这两个字段 → 按旧口径兜底（先行一步 2 分、不必走），历史用例照样跑。

## 常见错误

| 错误 | 后果 | 正确判据 |
|---|---|---|
| 三层无右区却跳过提问直接规划 | 玩家要打三结局时漏掉前置收藏品，整局白打 | 先问 Q1；没答就停在提问，工具也 exit 2 |
| 有右区还问三结局 | 多问一道不适用的题，玩家困惑 | 有右区 = 四结局线，不问；传了参数算错 |
| Q1=是、Q2=否，仍把先行一步按 2 分 | 求解器不会为它绕路，三结局前置收藏品整层错过 | `values["先行一步"]=15` + `must`（已探明）|
| 把「先行一步」当禁踩/白走格 | 少一个 15 分必走点 | 它是正收益普通节点，15 分 |
| 用二/四层的先行一步距离带套三层 | 候选坐标错，白走 | 三层只有 2–4（`06-距离表`）|
| 先行一步已探明却仍列候选 | 让玩家去找一个已经找到的节点 | 已探明 → 直接进 must，候选返回空 |
| 把候选坐标当成「必是先行一步」 | 走错格、路线全歪（除非只剩 1 格） | 候选只是「可能」；1 格时才可判定 |
| 用四层/五层的右区规则处理三层无右区 | 预留 AP、右区必走点复活 | 无右区局整层按左区求解（`25`）|

## 实现位置

| 文件 | 作用 |
|---|---|
| `tools/rules.py` | 三结局状态/归一化、`layer3_answer_errors()`、`layer3_scope_errors()`、`three_ending_need_xianxing()`、`THREE_XIANXING_VALUE=15`；`layer_values(3)` 在 `three_ending_need_xianxing()` 时给先行一步 15 分 |
| `tools/build_scenario.py` | `derive_must()` 把已探明的先行一步锁进必走；`xianxing_candidates()` 按距离带 2–4 算候选；CLI 参数/闸门/scenario 字段 |
| `tools/route.py` | 右区判定之后过闸（`--three-ending`）；打印候选与提示；路线一格候选都不经过时补 ⚠️；scenario 落 `three_ending` |
| `tools/observe.py` | `--three-ending` 透传 + 同一道闸（免得白跑一次 route） |
| `tools/apply_config.py` | 手工管线：写 `values["先行一步"]`（15 / 2）、已探明时补 `must`、落 scenario 字段 |
| `tools/pool_candidates.py` | `--xianxing`：只列先行一步候选坐标（手工 scenario 用） |
