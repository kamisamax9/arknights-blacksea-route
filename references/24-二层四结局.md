# 二层「四结局」问询（2026-10-30 玩家新增，强制）

## 什么时候问

**只要本局要规划二层，就先问——玩家口报「二层」，或截图/`observe.py`/标题 OCR 识别出二层，都算。**
问询在**求解之前**，还没问就调 `route.py` / `observe.py` / `build_scenario.py`，工具会直接
`❌ exit 2`，不会先按旧口径算一版。

同一局二层的滚动重算沿用答案（scenario 里的 `four_ending` / `four_ending_pre`），不必重复问；
换了新对局/新二层要重新问。

## 全程追猎：问 1 个问题

> **本局是否要打四结局？**

| 回答 | 二层险路尽头 | 二层险路小径 | 参数 |
|---|---|---|---|
| **要** | **8 分**（四结局道具），**必走 1 次** | 0（中继） | `--four-ending 要` |
| **不要** | **0 分**，**不再必走**（可作 0 分中继） | 0（中继） | `--four-ending 不要` |

> **「必走」不是「值 8、可选」**：`route.py` 会把选中的尽头塞进 `must`（两个候选取最优），
> `build_scenario.py` 会把离起点最近的那个写进 `must`——否则求解器可能为了 10 分居民据点
> 跳过四结局道具。若图上没有尽头，`route.py` 会如实 ❌。

## 险路尽头：问 2 个问题

**Q1：本局是否要打四结局？**

- **不要** → 二层险路小径 = 险路尽头（**8 分**），**小径可作二层可选终点**；`--four-ending 不要`
- **要** → 继续问 **Q2：是否已获取四结局前置藏品？**
  - **已获取** → 二层险路小径 = 险路尽头（**8 分**），**小径可作二层可选终点**；
    `--four-ending 要 --four-ending-pre 已获取`
  - **未获取** → 按现有方案：小径收益 **0**，除非情不得已作为中继节点需要进入，否则不进小径；
    **二层终点为险路尽头**；`--four-ending 要 --four-ending-pre 未获取`

> 险路尽头模式下，二层的**险路尽头始终按 8 分**计（它仍是本层主终点，四结局=不要 只是让
> 小径也升到 8、可作可选终点）。这是玩家 2026-10-30 口径的直读，不要自行把尽头改成 0。
>
> **前置藏品最终决定三/四/五层有没有右区，但不能用二层入口的 Q2 推断**：
> 前置藏品可能在二层过程中才拿到，玩家也可能直接从三层开始对话。
> 右区有无以三/四/五层实际截图为准；拿不准就问玩家「本局是否存在熄日余径？」。详见 `25-右区有无.md`。

## 分支总表（给工具/写 scenario 用）

| 终点模式 | `four_ending` | `four_ending_pre` | 二层 `values["险路尽头"]` | 二层 `values["险路小径"]` | `final_type` |
|---|---|---|---|---|---|
| 全程追猎 | 要 | — | 8 | 0 | 无（层在 AP 耗尽处结束；尽头按必走点处理） |
| 全程追猎 | 不要 | — | **0** | 0 | 无 |
| 险路尽头 | 要 | 未获取 | 8 | 0 | `["险路尽头"]` |
| 险路尽头 | 要 | 已获取 | 8 | **8** | `["险路尽头","险路小径"]` |
| 险路尽头 | 不要 | —（不问） | 8 | **8** | `["险路尽头","险路小径"]` |

- **二层两种例外下小径是硬终点**：进入即结束——两个 8 分终点只能选一个，避免「小径 8 + 尽头 8」双计；
  scenario 同时写 `final_type=["险路尽头","险路小径"]` 与 `hard_final_types=["险路尽头","险路小径"]`。
- 一/四层的小径才是**软终点**（可停可续）；二层未获取前置藏品时小径不是终点（0 分中继）。
- 险路尽头是**硬终点**：碰到即结束，之前不许进。
- 两种模式都**永不 block 小径**；二层尽头也永不 block（只是价值不同）。

## 未回答时的兜底

- CLI（`route.py` / `observe.py` / `build_scenario.py`）：**二层缺答案直接 exit 2**；
  险路尽头 + 四结局=要 但缺 Q2 也 exit 2。报错会写清缺的是 Q1 还是 Q2。
- 旧 scenario / 直接读文件的 `route_solver.py`：没有 `four_ending` 字段 → 按旧口径
  （要 + 未获取，尽头 8 / 小径 0）兜底，保证历史用例还能跑。
- `apply_config.py`：命令行参数优先，其次读 scenario 字段；都没有则按旧口径。

## 常见错误

| 错误 | 后果 | 正确判据 |
|---|---|---|
| 跳过问询，按旧口径给尽头 8 | 玩家不打四结局时多走 1 步、少拿别的收益 | 二层先问，没答就停在提问 |
| 把「小径=8」写到所有分支 | 四结局=要且前置未获取时，小径被当成终点，路线提前收尾 | 只有「Q1=不要」或「Q1=要且已获取」才升到 8 |
| 四结局=不要 时把尽头也改成 0（险路尽头模式） | 玩家口径里尽头仍是 8，会少报分/误判终点 | 见上方「分支总表」 |
| 把小径=8 的分支做成**软终点** | 穿过小径再去尽头 → 「8 + 8」重复计分 | 二层这两种例外下小径是**硬终点**（`hard_final_types` 含小径） |
| 把答案带到别的层 | 非二层传 `--four-ending` 会被工具直接判错 | 参数只在二层有意义 |

## 命令示例

```bash
# 全程追猎 · 二层 · 不打四结局（基础 AP 5）
python tools/route.py 截图 --layer 2 --config 4 --ap 5 \
    --four-ending 不要 --items "标准引擎:1"

# 险路尽头 · 二层 · 打四结局、已获取前置藏品（小径=8、可作可选终点；基础 AP 6）
python tools/route.py 截图 --layer 2 --config 4 --ap 6 --end-mode 险路尽头 \
    --four-ending 要 --four-ending-pre 已获取 --items "标准引擎:1"

# observe 同样透传
python tools/observe.py --end-mode 险路尽头 --four-ending 要 --four-ending-pre 已获取 --explain
```
