# 已知坑（我犯过的错，别重犯）

1. **y 轴方向**：表里 y=0 必须在最下排。曾整表上下颠倒过一次。
2. **斜向不能走**：徒步 4 连通；地图上两点相邻 ≠ 能走通，必须查边表。
3. **别用像素猜连线**：从截图推邻接关系错误率高，宁可要用户报坐标或查已固化的构型表。
4. **空地要计入路费**：(3,0) 这类空地走上去 0 收益但花 1 AP；能用斜跳越过就绕。
5. **树根 +2 AP 别忘**：它会改变整层预算（六层尤其致命）。
6. **识别阈值不是全局规则**：亮度 > 0.8 判定为"有边"只对**四层**成立（四层的模糊边经玩家核对确实全部不连通）。
   **二层不适用**——2026-10-24 复查发现二层有 **10 条暗竖线**（多为连到险路尽头的路）被误判成不连通，已补全。
   → 处理任何新层的图时，先用「连线亮度 − 平行偏移线亮度」的**对比度判据**复核，并把存疑边**放大目视**，不要一刀切。
7. **探明沿边、不沿方向**：网格上直接相邻但**没有边相连**的节点不会被点亮（曾按"四方向最近节点"推图，结论全错）。踩空地会一次性点亮 2–4 格，是最高效的侦察动作，别只当路费。
8. **手推邻接必错**：写路线前必须把边表喂给 `tools/route_solver.py --check` 跑一遍。曾把 `(0,1)-(0,2)` 当成通边（二层构型7 里第 0 列的竖线断在 y=1..2），导致整条路线第一步就走死。**顺序永远是：抄边表 → 校验 → 再优化**。
9. **加 AP 的节点必须写进 `grants`**：树根 +2、**羽瞰点 +1（进 1 给 1，净值 0）**、安全的角落 +2（50%）。漏写的话求解器会把它当纯成本绕开——二层那局就因此少算了 1 分，是玩家指出来的。**净 0 ≠ 要花钱**：羽瞰点当跳跃落点等于白赚一次开图。
10. **先判"格子有没有节点"，再判"有没有边"**（2026-10-24 重大教训）：
    建表时若只测两格间的连线亮度，会把**空格的背景辉光**读成路，造出**幽灵边**。
    必须先做节点存在性判定（格内最大亮度 ≥ 100 视为有节点），**边只在两端都有节点时成立**。
    三层因此删掉 18 条幽灵边。
11. **"连线很亮" 不能反推 "两端有节点"**：曾被 L6 的 `(1,4)-(2,4)`（连线亮度 1.00）骗过，
    提议"亮连线就直接收边"，玩家判定**删除正确**。亮连线可能只是背景/辉光。
    **节点存在性是唯一权威，连线亮度只用来判断"这条路通不通"。**
12. **靠边的格子（y 最高一排、x=0 / 最右列）节点亮度天然偏低**，容易被阈值误判成空格——
    核对时优先看这些位置，必要时请玩家确认。

13. **树根藏在「紧急作战」里，别漏**：树根=理想源，是紧急作战的一种，图标相近，看标签容易读成普通紧急作战。
    **树根的文字标签也是「紧急作战」，靠读字认不出来**——区别在**图标背景**：树根周围有一圈树根/藤蔓纹理。
    判定顺序：先列出本层所有紧急作战 → 逐个看背景 → 带树根纹理的是树根 → 写进 `grants`（+2 AP）、按 15 分估值。
    漏了它 = 漏 2 点行动力 + 10 分价值（2026-10-25 三层 L4 那局，我算成 34 分/6 步，实际 46–47 分/8–9 步）。
14. **羽瞰点是「白赚的中继」**：进 1 退 1，净值 0，所以**顺路必进**（还顺手开图）；不顺路不必为它绕。
    写成 `grants` 后，它会让总操作数 +1（6 AP + 树根 2 + 羽瞰点 1 = 9 步）。
15. **模式开关没问就动手 = 全局错价**（2026-10-29 新增）：
    本技能有**两个相互独立的模式开关**（SKILL.md 〇·〇），新对话第一次规划前**都要问**：
    · **分队模式**——N16文明开化（**通过追猎进入二~六层时大概率出现理想源**、打掉 +2AP+4藏品；
      推荐搭配全程追猎使用）／普通分队（不保证有理想源、打掉不回复、价值=紧急作战）；
    · **终点模式**——全程追猎（尽头/恶敌照旧禁踩，层在 AP 耗尽处结束）／
      险路尽头（一/四层最后一步必须进险路尽头**或险路小径**；**二层默认只能进尽头**，
      但四结局=不要 或 要且已获取前置藏品时小径=8、可作可选终点；
      三/五/六层必须进险路恶敌，之前不进硬终点）。
    典型错误（每个开关两个方向，共四类）：
    · 普通分队局按 N16文明开化算 → 追着要理想源、凭空预留 +2 AP、树根当 15 分必走点；
    · N16文明开化局按普通分队算 → 漏 +2 AP 和 10 分，路线整体偏短；
    · 险路尽头局按全程追猎算 → 尽头/恶敌被 block，最后一步根本落不到终点上（直接 ❌）；
    · 全程追猎局按险路尽头算 → 白白把尽头/恶敌放行，还强制绕去终点，步数全错。
    → **判据**：新对话先问两个开关；同一局逐层沿用；
    工具链用 `--mode` / `--end-mode` 透传，scenario JSON 带 `"mode"` / `"end_mode"` 字段；
    普通分队下「未报理想源」、险路尽头下「终点权重暂定 0」都是**正常输入**，不许当错误报警。

16. **二层不问四结局就开算 = 整层价值错**（2026-10-30 新增）：
    二层（玩家口报或截图识别都算）必须先问「本局是否要打四结局？」：
    · 全程追猎：答「要」→ 尽头 8、必走 1 次；答「不要」→ 尽头 0、不必走；
    · 险路尽头：答「要」再问「是否已获取四结局前置藏品？」——已获取 → 小径=8、可作可选终点（硬终点，进入即结束）；
      未获取 → 小径 0、不作终点；答「不要」→ 小径=8、可作可选终点（同为硬终点）。
    典型错误：跳过问询按旧口径给尽头 8（玩家不打四结局时多走一步、少拿别的收益）；
    或把「小径=8」写到所有分支（前置未获取时它仍是 0）；或把小径 8 做成软终点（穿过小径再去尽头会双计 8）。
    → **判据**：`route.py` / `observe.py` / `build_scenario.py` 在二层没收到 `--four-ending`
    会直接 exit 2（险路尽头+要还缺 `--four-ending-pre` 也 exit 2）；这不是工具坏了，是先问。

17. **三/四/五层没有右区是合法局面，不是截图切边**（2026-10-30 新增）：
    未获取四结局前置藏品时，这三层只有左区，且左区在屏幕/截图里**居中**。
    · 仍按完整宽度 11/12/14 列读 → 格点越界/整体错列，起点与构型全错；
    · 仍按三/四/五层预留 3/4/5 AP → 左区预算被砍，少走 3–5 步；
    · 仍保留右区必走点 → 永远走不到，整层判 ❌。
    → **判据**：`label_ocr.choose_layer_cols()` 已按「完整宽度 vs 左区宽度」自动选列并输出
    `has_right`；无右区时 `route.py` 不拼右区、不预留 AP、不检查「右区没进去」。
    完整宽度截图但右区一格没读到才是真异常（重截）；左区居中 = 无右区，不要反复重截。

18. **三层无右区不问三结局 = 整局白打**（2026-10-30 新增）：
    三层**没有右区**时，本局没走四结局线，可能在打三结局。不先问就按普通逻辑规划：
    · 玩家打三结局、但前置收藏品还没拿到 → 没人去「先行一步」，前置收藏品整层错过；
    · 反过来，替玩家默认「要」并给先行一步 15 分 → 不打三结局的局白绕路。
    · 先行一步还藏在未知诡秘里时只给个 15 分期望、不列坐标 → 玩家不知道去哪找。
    → **判据**：先问「本局是否打三结局？」；答「要」再问「是否已获取三结局前置收藏品？」。
    答「否」→ `values["先行一步"]=15` + `must`（已探明）；**未探明就列出距层起点 2–4 步的
    全部未知诡秘坐标**并提示玩家去找（`26-三层三结局.md`）。有右区 = 四结局线，这题不问。

19. **把 `pip` 的解释器当成跑脚本的解释器 → 误判「本机缺依赖」**（2026-10-30 新增）：
    事故：用 **Dsh 自带 Python 3.12**（`...\dsh-runtimes\...\dependencies\python\python.exe`）
    跑 `tools/*.py`，报缺 `rapidocr_onnxruntime` / `scipy`，于是写成「本机缺依赖、实图回归留待下次」；
    实际系统 Python 3.11（**PATH 上的 `python`，`pip` 装的就是它**）两样都齐。
    · 更隐蔽的一次：`label_ocr._sprite_evidence` 的 `from scipy import ndimage` 被
      `except Exception: pass` 吞掉 → 滚动阶段「站在带标签节点上」的判定**静默关闭**，
      `selftest_lattice` 10/11 失败，被误当成代码坏了。
    → **判据**：① 先跑 `python tools/pyenv.py`（当前解释器 + 缺什么 + 本机其他齐全解释器）；
    ② 任何「缺依赖」结论都必须带上 `pyenv.py` 打印的**解释器路径**，不许只说「本机缺」；
    ③ scipy 缺失现在会打 ⚠️（不再静默），`selftest_lattice` 的 10/11 按「跳过」计。


20. **白圈徽章是 6 种字形，不是「有/无」**（2026-10-30 新增）：
    · 泪之聚落（**骷髅面罩**，0 分）vs 线人（**蜘蛛**，三层 10）——只按「有徽章」或只按「宽/高」
      都会把 0 分格当 10 分格；
    · **橡果 = 迷藏**：**所在节点收益 +12 分**（2026-10-30 改口径，旧的「不改价 + 同分优先」已废）；
      带橡果的林间空地**不再是墙**（`block_except` 放行、地基 0 → 12 分）。
      仍然**不要**写进 `must`（压在禁踩格上会判必走走不到）；
      也**别**按 `-99 + 12` 算（那是 -87，等于没放行；地基走 `rules.acorn_base_value()`）；
    · **乌鸦 = 流窜居民**；**羊角 = 三结局失与得**、**狼头 = 无效验尸**——后三类都**不改价**。
    · 实测三个漏检：① 旧 20px 网格聚类把「贴着作战图标的狼头徽章」并进 >800px 大块、
      整块丢掉 → 四层 (3,3) 无效验尸整格漏；② 白块下限 0.20×sp=24.8 把 24px 的乌鸦徽章漏掉；
      ③ 徽章贴着**亮图标光晕**时像素级连通域仍会合并（五层 (3,2) 失与得 44×30 大块），
      二值 IoU 掉到 0.37；红背景上乌鸦又过不了 `is_resident` 色度闸 → (2,3) 漏检。
    → **判据**：`pixel_probe.badge_glyph()` **灰度 NCC**（≥0.55，±6px 平移 + rad±1）；
    合并块用 `_glyph_scan()` 在块内扫（含 ±2px 细扫）；`detect_badges` **不用色度闸**
    （色度闸只留给 `detect_residents`）；`label_ocr --badges` 自动按格点宽度定列。
    详见 `27-三结局徽章.md`。

## 距离与推断三坑（2026-10-25 三层实战）

**坑 1：距离基准用错**
用**当前位置**算 (4,2) 得「2 步」，据此排除了「秘境行商(3–6) / 误入奇境(5–6)」；
换成**层起点**是 6 步，两者都成立，判断完全反转。
→ 距离表永远按层起点算，`--dist-from` 必填。

**坑 2：只会用距离带，不会用数量约束**
漏了「三层紧急作战共 2 个、理想源占 1 → 其余凶戾恰有 1 个」。
补上后能锁定 (5,3)/(5,4) 互补，只打紧急、绕开普通。

**坑 3：用边表否决道具可达性**
判定 `(5,4)` 是死胡同（边表只连 (5,3)）并据此否决路线；
实际上 `(4,3)→(5,4)`、`(5,4)→(6,3)` **都是斜向相邻**，用标准引擎/鸣笛各 1 步。
**边表只约束步行，不约束道具。**
8. **分辨率必须用 1920×864（20:9），16:9 不行**（2026-10-27 玩家实测确认）：
   **1600×900 和 1920×1080 下，三层及以后的「右区」最右一列会被「行动力」徽章压住**，读不到节点。
   原因是徽章固定在右上角，16:9 画面窄、地图右缘正好落到徽章光晕下面；20:9 多出来的横向空间把右区推到徽章左侧。
   → **判据**：截图后先看右区最右列（三层 x=10、四层 x=11、五层 x=13）能不能读出节点；读不出就是画幅问题，不是识别算法问题。
   → 1080 只在**一、二、六层**（无右区）可用；带右区的三/四/五层一律 864。
9. **走过的节点标签会消失**：OCR 读到的格数会随推进而减少，这是**正常消耗**，不是漏读、也不是标定失败。
   2026-10-27 一层：18:06 那张读到 10 个标签，18:40 只剩 6 个——因为中间走了几格。
   → 判据：如果只是**格数变少**、且剩下的格子仍在构型内，自检会照常通过，**不要重标定**。
   → 只有当**同一张图、同一时刻**读出越界格或维度不符时，才说明标定有问题。
10. **「实战固化」表只能用来读结构，不能用来读节点类型**

    `17/09/1x-*构型` 里的「实战固化」段落，是**某一局的节点快照**。
    跨局不变的只有两样：**边表（连通结构）** 和 **定点节点**（一层 (1,2)/(4,1)=诡意行商）。

    | 可以拿来用 | 不能拿来用 |
    |---|---|
    | 哪条是上链、哪条是下链 | 「这格是诡秘」 |
    | 哪里有死端、哪里是死路终点 | 「这格是凶戾」 |
    | 哪几格构成主环路 | 「这格是空地」 |

    2026-10-27：有会话拿固化表质疑 OCR——「固化表说 (3,0)(3,1) 是诡秘链、(1,1) 是凶戾，
    但 OCR 把 (3,2) 读成了凶戾」。**OCR 是对的**；那一局本来就变了样子，
    截图放大可见 `(3,2)` 的标签明明写着「未知的凶戾」。

    **判据：文字标签与固化表冲突时，永远信文字标签。**

11. **图标形态不能用来判节点类型——文字标签可靠得多**

    容易被当成「捷径」的经验规则：

    | 图标 | 常被这样认 |
    |---|---|
    | 肺 | 凶戾 |
    | 胚胎 | 诡秘 |
    | 兽首 | 作战 |

    **这条不能用**，因为这些图标对应的是**一类**而不是一个类型：

    | 图标 | 实际可能是什么 |
    |---|---|
    | 肺 | 未知的凶戾 **和** 紧急作战 |
    | 胚胎/蓝色圆 | 未知的诡秘、不期而遇、得偿所愿、安全的角落…… |
    | 兽首 | 作战 **和** 紧急作战 |

    另外：同一类图标在不同层、不同状态下还有配色/描边差异（点亮、已探明、伪装），
    色度规则在四层的深青「未知的诡秘」上就漏检过 1/3。

    **结论：节点类型只认地图上的文字标签（OCR）。图标只用来定位坐标（且要反过来被标签校验）。**
12. **求解器会输出「回头步」，看到就必须逐条验证**

    **它不知道各层的具体结构**，所以「重踩一个已访问的格子」在它眼里完全合法：
    那一格值 0，不违反任何约束，只要后面能换到更高的总分它就照走。

    于是它可能给出一个**带回头、且总分没到顶**的「最优解」——
    因为它是在**给定的图和定价**下最优，而不是在你理解的走法里最优。

    ### 判定流程

    1. 输出里出现 `↺ 回头步` → **不许放过**
    2. 逐条问：这一步回头，是否是为了到达后面那个得分点？
       - 是 → 必要（例：一层 `(2,0)→(2,1)→(2,2)`，`(2,2)` 只能经 `(2,1)` 到达）
       - 否 → 纯浪费，路线要重排
    3. 若还有剩余行动力，**先证明它真的无处可去**，再说「只能浪费」

    ### 2026-10-27 实例

    一层路线给出 `(2,0) 作战 → (2,1) 起点（0 分）→ (2,2) 作战 …`，
    当时把这步当成「同分替代」放过了，还写下「剩下 2 点只能浪费」。
    **那 2 点并不必须浪费** —— 「回头」和「点用不完」都只是被接受的现象，没有被验证。

    这条已加进求解器输出，每次都会打印：
    ```
    ↺ 回头步 1 处（重踩已访问格）：
       第 2 步重踩 (2,1)「起点」——值为 0
       → **必须逐条确认这一步是否必要**
    ```
13. **地图显示名 ≠ 实际类型：一张对照表，别再当矛盾**

    这些是**规则**，不是数据错误。每次开新会话都会有人拿它当「矛盾」来问，所以列死：

    | 实际是什么 | 地图上显示成 |
    |---|---|
    | **理想源（树根）** | **未知的凶戾** 或 **紧急作战**（它**永远没有自己的标签**，只能玩家口报坐标） |
    | **险路尽头** | **险路尽头**（点亮的那一个）或 **未知的诡秘**（伪装的） |
    | **诡意行商（一层定点）** | **未知的诡秘** |
    | 空地 / 起点 / 汇点 | 无文字（`∅`） |

    **判据**：

    1. 先看「这一格有没有字」——没字就是空地/起点/汇点，不可能是树根或尽头
    2. 有字但和构型表冲突 → **以构型表为准**（伪装是设计）
    3. 树根永远不会自己出现，**必须玩家报坐标**（`--root c,r`）

    2026-10-27 实例：某会话把「(1,3) 显示未知的凶戾却被定为树根」和
    「(0,1) 显示未知的诡秘却被定为险路尽头」当成互相矛盾的证据，
    进而怀疑构型判错。**两件事同时成立，没有矛盾。**

    `route.py` 现在会把这类「显示 → 实定」逐条打印出来，不再需要人推理：

    ```
    显示 → 实定（地图上的名字是伪装，不是矛盾）：
      (0,1)  地图「未知的诡秘」 → 险路尽头（构型表定点）
      (1,3)  地图「未知的凶戾」 → 树根（玩家口报理想源）
    ```

| # | 坑 | 曾经的表现 | 判据 / 现状 |
|---|---|---|---|

## 同分比价：`<=` 剪枝会把「追平但更省」的解整段砍掉（2026-10-28）

**症状**：毛分相同的两条路线，求解器给出**更贵**的那条，而且看起来毫无理由。

**根因**：`best` 更新时明明有「同分比道具价」的 tie-break，但**上界剪枝用的是 `_ub <= best`**：

```
若「本路乐观上界」== 当前最优 → 直接剪
```

于是任何「只能追平」的分支在**追平之前**就被砍了，tie-break 永远没机会执行。
管道两头各自都对，接起来却没有「同分更省」这个语义。

**判据**（判决式，别改）：

| 条件 | 动作 |
|---|---|
| `ub < 最优分` | 剪（连追平都做不到） |
| `ub == 最优分` 且 `已花道具价 ≥ 当前最省` | 剪（追平了也不会更便宜；代价只增不减，所以是合法下界） |
| `ub == 最优分` 且 `已花 < 当前最省` | **保留，继续搜** |

**实现**：分两段跑，别想一步到位。

1. **阶段 A**（快，老行为）：只最大化毛分，`ub <= 最优` 就剪。证明最大分 S。
2. **阶段 B**（可选）：在「毛分必须追平 S」的前提下最小化道具价，用上表判据。
   代价沿路径**累加**（`moves()` 多返回一个 `dcost`），不再每步遍历道具
   —— 这正是 2026-10-27 那次「把比价塞进 DFS 就 14s→60s」的真正原因。

**为什么必须分段**：`_ub == S` 的壳层可能极大。
实测 73 分那局：壳层状态上百万，单阶段硬搜 20M 状态都跑不完；
分段后 A 保持 45s 的原速，B 只吃「A 剩下的预算」。
**B 没跑完时必须说「可能还有更省的同分解」，不许把贵的说成最省**（`cost_proven` 字段）。

**回归锁**：`selftest_solver.py` 的「同分更省道具的路径必须保留」
（徒步链 0 元 vs 原理链 16 元，都得 10 分 → 必须给 0 元那条）。

## 必走点（must）：清单口径与「为什么它不提速」

**清单**（`build_scenario.derive_must`，2026-10-28 玩家口径）：

| 节点 | 何时必走 |
|---|---|
| 理想源（树根） | 只要图上有，**任何层**都必走 |
| 秘境行商 / 紧急作战 | 二~五层，且**已探明** |
| 右区（缝之后）的 作战 / 紧急作战 / 未知的凶戾 / 凶戾 | 必走（含改名后的「右区作战」等） |
| **五层右区的诡意行商** | 必走（五层右区固定 1 个；03「五层行商 2–3 个全进」） |
| 不算 | 左区未知凶戾、右区诡秘、命运所指、空地、安全的角落 |

> 五层右区那个行商值 **12 分**，是右区里唯一的非战斗高价值格；
> 未点亮时它显示成「未知的诡秘」，那时**推不出坐标**，只能等探明后再算必走。

**前提事实**：先锁死必走点（树根、已探明行商/紧急、右区作战类），再在「必须覆盖」的解里穷举，
理论上能砍掉分支。**已照做**（硬约束 + 预算剪枝 + 走法排序 + 漏点报告 + 走不到时回落），
但四个真实场景实测**没有变快**：

| 场景 | 无约束（状态/耗时/分） | 有必走（状态/耗时/分） | 必走剪枝命中 |
|---|---|---|---|
| L3-regression-73 | 16.9M / 54.6s / 73 | 16.9M / 54.5s / 73 | 0.04% |
| L3-A_全道具 | 2.57M / 11.0s / 57 | 2.57M / 11.1s / 57 | 10% |
| runs/L3-L4-0020 | 659k / 2.8s / 89 | **896k / 3.9s / 86** | 28% |
| L3-run3 | 6.7M / 27.5s / 54 | 6.7M / 25.6s / 54 | 0.09% |

**为什么**：

1. 判据「没踩的必走点数 > 还能走的步数」只在**行动力快花光时**才成立 = 叶子附近，
   那里子树本来就小。**剪叶子不改变搜索树的规模。**
2. 反向作用：必走约束排除了「省点的最优解」，`best` 变低（89→86）→ 按分数剪枝的上界变松
   → 状态数反而 **+36%**。

**结论**：穷举量的主项是「已访问价值集合 × 位置 × AP」这个状态空间，
不是「有没有走到某个点」。所以必走点**当规则层用**（漏了就报，不许安静给违规路线），
**别当加速手段**。真要提速就动上界（现在的 `ub` 完全不看可达性/墙）或分阶段求解。

## 空地当墙 + 分阶段：真正把搜索压下来的两刀（2026-10-28）

### 1. 空地/密道改成**真硬墙**（`sc["block"]`）

以前空地只是 **-99 分**：走上去等于自杀，但求解器仍把它当**中继**去展开——
白占状态，路线还可能在空地上来回试。现在直接从图里删格（`block` 列表），
不走进、不跳进、不占 mask。一层例外（空地是合法中继，`block` 只写密道）。

### 2. 三/四/五层分阶段：右区固定预留，左右各自求优

| 层 | 右区预留 | 左区预算 |
|---|---|---|
| 三 | **3** | `ap0 − 3` + 左区 grant |
| 四 | **4** | `ap0 − 4` + 左区 grant |
| 五 | **5** | `ap0 − 5` + 左区 grant |

右区段 = 预留 + 左区剩下的 AP，起点是左区终点，必走点/终点各自带自己的。

**实测（同一局，分阶段 vs 整体）**：

| 场景 | 整体 | 分阶段 | 差 |
|---|---|---|---|
| L3-regression-73 | 61.4s / 73 | **1.5s / 73** | 0 分，40× 快 |
| L3-A_全道具 | 8.5s / 57 | 0.1s / 56 | −1 分 |
| runs/L3-L4-0020 | 2.6s / 89 | 0.05s / 78 | −11 分 |
| L3-run3 | 26.2s / 54 | 0.4s / 52 | −2 分 |

**代价是真实的**：切换点被固定，跨区的组合收益就没了（0020 那局 −11）。
要最优用 `--joint`；要秒回用默认。

### 分阶段的三个坑（都踩过）

1. **进区件只看 cov 不够**。轮子是「直线 2 格」——左区终点离右区 3 格就够不着；
   融雪「只能落非作战」——右区全是凶戾时一个都落不了。判据必须是
   **从左区终点实际算一遍**：`COVER[cov]` 里有没有右区格，且 `only/exclude` 允许。
2. **左区会把进区件烧掉**。先按完整库存解左区，再检查「剩下的件够不够得着」；
   不够就**扣出那件真够得着的**重解左区（最多 3 轮，因为扣掉后左区终点会变）。
   ⚠️ 扣哪一件**必须按几何挑**，不能按「最便宜且覆盖类型合格」——
   2026-10-28 实测：左区终点 (2,2)、右区 (8,0)，轮子（2 元）够不着、原理（16 元）才行，
   旧逻辑扣了轮子 → 右区 0 分。
3. **右区改名破坏 `only` 前缀**：`"右区诡秘".startswith("诡秘")` 是假。
   展开逻辑现在**只有一份**：`rules.expand_prefixes` / `rules.land_ok`，
   `Solver.__init__` 和 `route.py::_can_land` 都调它。
   ⚠️ 只改求解器不改入口，会出现「入口打印『进区件：融雪 → (8,0) 右区作战』、
   求解器却拒绝 → 右区 0 分」的矛盾（2026-10-28 复查发现）。

   **`only` 和 `exclude` 必须一起展开，而且共用同一份「作战家族」常量**
   （`rules.COMBAT_PREFIXES` = 作战 / 紧急作战 / 普通作战 / 凶戾 / 未知的凶戾 / 树根 / 理想源）：
   * `only` 写窄了 → 拿着鸣笛进不了右区（凶戾、树根都是作战节点，树根在地图上就显示成紧急作战）；
   * `exclude` 写窄了 → **融雪会落进战区**（实测落到「右区凶戾」：
     exclude 只写了 作战/紧急作战，而凶戾是未知的作战）。
   两条都是「同一份常量没共享」导致的。
4. **进区件不跳过 `block` 的死格**（2026-10-28）。
   `_find_entry` 原来只问「COVER 里有没有右区格、only/exclude 允不允许」，
   **不看那格是不是已经被 `block` 删掉**。实测：左区终点 (6,0)，右区 (8,0)=空地、
   (10,0)=右区作战，手里只有报废轮子（直线 2 格）→ 入口打印
   「进区件：报废轮子 → 落 (8,0) 空地」，求解器把空地删了 → 轮子够不到 (10,0)
   → 右区 0 分、必走点回落。
   ⚠️ 隐蔽点：**`any` 类件（原理）会碰巧改落到真格上**，日志错但结果对，
   所以只有直线件/行商限定件才暴露。判据：落点必须是**求解器真能落的那格**
   （`_landable_right_cells` 先剔死格，再算几何）。
5. **三/四层的命运所指要硬删，别只写 -99**。分数是**求和**的，
   只要总分压得过 -99，求解器就会把命运所指当 0 价中转走过去。
   现在 `build_scenario.block_types` 把三/四层的命运所指一并 `block`
   （五层它是终点，绝不能删）。
6. **校验用的图必须和求解用的图一致**（2026-10-28）。
   回头步判定 `avoidable()` 原来直接拿原始 `edges`：三/四层命运所指、三层起空地、
   险路恶敌、险路尽头被 `block` 之后，校验仍把「绕经那面墙」当成一条真路 ——
   一条**不得不回头**的路线会被判成「可避免的回头步」→ 整体 ❌。
   **求解本身是对的，错在最后那道校验。** 现在统一用
   `route._adj_after_block(edges, nodes, sc["block"])` 建邻接。
   > 一般判据：**凡是「按图判断」的代码，都要问一句「它看的是哪张图」**——
   > 求解器删了格，校验器没删，就会互相打脸。

### 右区预算是**固定**的，不结转（2026-10-28 修正）

```python
"ap": reserve + max(0, ap_end)   # ❌ 旧：左区花不完的流到右区
"ap": reserve                     # ✅ 新：固定 3/4/5，左区剩下的算损耗
```

「剩余归左区支配」＝左区**可以**全花掉；花不掉就是损耗，不是右区的预算。
结转会让右区的实际步数随左区走势浮动，和玩家口径的 3/4/5 对不上。

### 左右区边界只能有一个来源（L8）

五层 L8 是 13 列、缝在 x=9，左区只到 **x=8**；常驻 14 列版左区到 x=9。
以前 `route.py` 把 lm 收成 8，而 `right_zone()` 自己用 `LEFT_MAX[5]=9` ——

## 求解器的性能三条（2026-10-28，实测有效）

热路径是 `moves()` + `ub()` + 每步路径复制；三条都只改实现、不改语义：

| # | 改动 | 效果 |
|---|---|---|
| 1 | `ub` 按 `(mask, k)` 缓存（上界只取决于「已访问格集合 + 还能走几步」，与访问顺序无关） | **命中率 96–99%**，纯赚 |
| 2 | `_precompute_moves()`：徒步邻居 + 每个道具在每个位置的可落点一次性算好（`portal/bit/vals/grants` 查询、`only/exclude` 前缀匹配全部搬出热循环） | 每状态耗时约**减半** |
| 3 | 路径用 `stack.append/pop`，**只在更新最优解时**才复制 | 同上（原写法每个节点复制整条路径） |

实测（73 分用例，整体求解）：每状态 **3.9µs → 1.9µs**；
L3-run3 26.2s → 15.1s、A_全道具 8.5s → 5.8s、0020 2.6s → 1.9s。

> 注意：73 分那局**状态数反而涨了 38%**（15.7M → 21.7M），不是变慢，是
> `only/exclude` 的「右区+名」展开让鸣笛能落到右区作战上 —— 可行动作变多的语义修正。
> 报「变慢了」之前先看**状态数**和**每状态耗时**这两个数，别只看总时间。

## 「零件箱满 → 不进行商」是**严重误判**（2026-10-28 玩家纠正）

**症状**：零件箱 9/12 或 11/12 时，会话判断「去了也装不下新东西，所以放弃秘境行商」。

**为什么错**：行商有**两个**作用，容量只影响其中一个。

| 作用 | 满包时 |
|---|---|
| **买**新件 | 确实装不下 → 单看这条像白跑 |
| **卖**低稀有度/低价值件 → 腾格 + 换源石锭，再买高级件 | **价值最高**：满包恰恰是「该置换」的信号 |

**正确判据**：跳过行商只允许三个理由——**这层没有行商 / 已经进过 / 去了会超时**。
「包满」永远不是理由。

**适用范围**：所有层、所有行商（二层秘境行商、三层秘境行商、五层诡意行商「2–3 个全进」）。
满包进店的动作顺序：**先卖 → 再买 → 最后清掉带不出本层的位移件**。

> 这与「同效果道具先用剩余次数少的」是同一条经济逻辑：**腾格本身就是收益**。
