# 边表构建与校验（方法论文档）

> 2026-10-24 三层/四层返工后固化。**重建任何一层的构型表，都必须按本文流程**，
> 否则会重犯「幽灵边」错误——那是这套资料里代价最高的一类错误（会让路线第一步就走死）。

## 一、核心原则：两件事分开判

| 问题 | 判据 | 阈值 |
|---|---|---|
| **这一格有没有节点？** | 格内**最大亮度** | ≥ **100** |
| **这两格之间有没有路？** | 两格之间**连线亮度分数** | > **0.8** |

**边 = 两端都有节点 且 连线亮度 > 0.8。**

### 为什么必须分开

早期只测连线亮度，结果**空格的背景辉光**被读成"路"，造出大量不存在的边。
三层因此返工删掉 18 条幽灵边，四层 7 条。

### 三个反例（都经玩家裁决）

| 现象 | 结论 |
|---|---|
| 连线亮度 **1.00**，一端是明确节点 | **仍可能是假边**——亮线可能只是背景/辉光。玩家否决了"亮连线反推有节点" |
| 两端都亮（142/142），连线 0.29 | 有节点、**确实不连通** → 删除正确 |
| 一格亮度 56–97，连线 0.94 | 该格**没有节点** → 删除正确 |

> **节点存在性是唯一权威。连线亮度只回答"路通不通"，不回答"格子存不存在"。**

## 二、图标不是普通节点，必须强制标记

「险路恶敌」「险路尽头」是**暗盘 + 辉光**的图标，亮度介于空格与普通节点之间（110–160），
用 100 阈值时**时对时错**，用 130 则必错。所以**先用颜色把它们定位出来，强制标为有节点**。

| 层 | 图标 | 颜色 | 每构型数量 |
|---|---|---|---|
| 三 / 五 / 六 | **险路恶敌** | 红/粉（R>110 且 R−G>45、R−B>45） | **1 个** |
| **四** | **险路尽头** | 黄绿（G>120 且 G−B>60、G≥R−10） | **3 个** |
| 一 / 二 | 无 | — | — |

> **四层没有险路恶敌，只有 3 个险路尽头。** 别把两层的图标搞混。
>
> 图标不进路线（除四结局=要 时二层尽头拿道具），但**它的格子必须算作有节点**，
> 因为连通性要经过它——把它当空格会连带删掉一整片真边。

## 三、网格拟合

用**「亮度 > 0.8 的边数最大化」**作为目标拟合 `(x0, dx, y0, dy)`，不要用亮度峰值定位——
峰值会被玩家图标、图标辉光带偏，导致整列错位（三层曾因此整表错位）。

- 三层：`dx/dy ∈ [125,150]`
- 四层：`dx/dy ∈ [120,152]`
- 五层：`dx/dy ∈ [118,140]`
- 五层 L8 特殊：只有 **9 列**（缝在 x=9），用锚定格 `L8_COLS/L8_ROWS`（由起点 (6,3) 反推）

## 四、校验流程（三步，缺一不可）

1. **对比度判据**：`连线亮度 − 上下/左右各偏移 10px 的平行线亮度`
   → 找出「表里没有但对比度高」的候选边（漏判）与「表里有但对比度极低」的边（误收）。
2. **放大目视**：把候选边裁 3 倍图、排成对照表看。**像素判据只能提出候选，不能定案。**
3. **玩家裁决**：把删除/新增清单连同「端点亮度 + 连线亮度」交玩家逐条确认，结果写进例外清单。

## 五、例外清单（人工裁定必须持久化）

`tools/offline/exceptions.json`：

```json
{ "whitelist": [{"layer":3,"config":3,"edge":[[4,3],[4,4]],"why":"..."}],
  "blacklist": [{"layer":3,"config":9,"edge":[[3,3],[3,4]],"why":"..."}] }
```

`tools/offline/edge_builder.py` 会自动套用，**没有它就跑不出定稿结果**（三层差 2 条）。

## 六、各层核对状态

**先看证据等级**（2026-11-02 定；逐层登记在 `CHANGELOG.md` 顶部「边表证据等级」总表，
每份构型文件头也各写一行）。**工具跑通 ≠ 对过原图**，这四个等级不许混写：

| 等级 | 定义 | 谁定的 |
|---|---|---|
| **A 原始表** | 直接来自 xlsx，未经程序重建 | 制表人 |
| **A 逐条核对** | 程序重建 + **玩家逐条裁决**（删边/补边都过人的眼） | 玩家 |
| **B 机械判定** | 程序重建 + 节点存在性/幽灵边扫描，**没有**逐条裁决 | 工具 |
| **C 形状表** | 右区连通性按格数/形状查表（表来自 xlsx 图，**未逐条边人工裁决**）；多解时回退四邻接并打 ⚠️ | 制表人 + 工具 |

| 层 | 状态 | 等级 | 说明 |
|---|---|---|---|
| 一层 | ✅ 原文 | **A 原始表** | `一层构型图.xlsx` 的文字边表，最可靠 |
| 二层 | ✅ 已修正 | **B 机械判定** | 补入 10 条暗竖线（原判为不连通，实为连到尽头的暗路）——**未逐条核对** |
| **三层** | ✅ **定稿** | **A 逐条核对** | 18 条幽灵边经玩家逐条确认；`edge_builder` 可复现 |
| **四层** | ✅ **定稿** | **A 逐条核对** | 7 条删除经玩家逐条确认 |
| 五层 | ✅ 通过 | **B 机械判定** | 节点判定未发现幽灵边（仅两条恶敌相关，已白名单）——**未逐条核对** |
| 六层 | ✅ 原文 | **A 原始表** | `六层构型图.xlsx` |
| 三/四/五层右区 | ⚠️ 形状表 | **C 形状表** | 四层永远多解（1↔4、2↔3 格集互相包含），要空地圆点才唯一 |

> 引用规则：**B/C 级边表上的结论不许说成「已充分验证」**；判词里「右区边表未验证」就是 C 级的自动出口。
> 要升 A，只能拿原图逐条核对（本文第四节的「三步校验」）。


## 七、复现命令

```bash
# 三层（红=恶敌）
python tools/offline/edge_builder.py <三层图目录> --layer 3 --out e3.json
# 四层（绿=尽头，3 个）
python tools/offline/edge_builder.py <四层图目录> --layer 4 --out e4.json
# 五层（L8 需锚定，只有 9 列）
python tools/offline/edge_builder.py <五层图目录> --layer 5 --anchor 8 --out e5.json
```

（这三条是**离线建表**命令，不在每局主链路上；2026-10-30 起工具移入 `tools/offline/`。）

输出每张图的 `grid_x/grid_y`、`icons`、`nodes`、`edges`、`n_edges`，可直接与表比对。


## 八、实战截图识别（**OCR 为主**，像素只做定位）

**构型图 ≠ 实战截图**，两者要不同的工具：

| 输入 | 工具 | 目的 |
|---|---|---|
| 构型图（无 HUD、纯色底、平铺） | `tools/offline/edge_builder.py` | 建**资料表**（每构型的节点与边） |
| 实战截图（有 HUD、带光晕、有标签） | `tools/board_read.py` / `tools/label_ocr.py` | 读**当前这一局**的节点表 |

### 做法（2026-10-27 定稿）

1. 标题 OCR 认层（`board_read.LAYER_TITLE`），认不出就报错，**不许退回 11×5**；
2. 节点**类型**只读标签文字（RapidOCR + 编辑距离校正回词表）；
3. 格点由标签位置聚类（`label_ocr.choose_lattice`）+ 小人像素整列自愈（`align_lattice`）；
4. 像素响应图（`read_scene.response_map`）只做两件事：标签↔图标配对、一/二层暗空地补格。

### 为什么不用颜色/饱和度判类型

- 四层深青「未知的诡秘」和暗背景色度几乎相同，漏检 1/3；
- 诡秘系图标一对多（诡秘 / 不期而遇 / 得偿所愿 / 安全的角落），凶戾与紧急作战同族；
- 饱和度会把**整片光晕**连成一个巨块（实测最大连通域 56000 px），图标反而找不到。

> 历史（2026-10-26）：响应图方案在三层实战截图（1596×891）上拟合出 11×5、节距 126px、
> 检出 23/26 个节点，漏的 3 个全是暗图标。它给的是「**有没有**节点」，
> 给不了「**是什么**」——所以现在只保留 `fit_lattice` / `response_map` 作为库函数。

### 结论

像素能给出**可靠的骨架**（格点对齐、有没有节点），但**类型必须读字**。
漏检的暗图标看 `label_ocr.py` 的标注图或人眼补；连通性永远只信构型表。

## 九、如果将来加新层

1. 先确认：层宽、图标种类与数量（红/绿/无）、格子间距范围；
2. 用 `tools/offline/edge_builder.py` 跑一遍，与现有表逐构型比 `n_edges`；
3. 差异逐条走「对比度 → 放大 → 玩家裁决」；
4. 裁决结果写进 `tools/offline/exceptions.json`，并在 CHANGELOG 记一笔。
